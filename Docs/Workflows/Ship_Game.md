- `engine`／`boiler`／`shaft`（kotoko，Tim 2026-10-15：「遊戲中如果引擎被破壞 引擎提供的額外動力要消失（且煙會停掉）因此需要標記」）：✅ 遊戲讀了（Blockside 8c1ef46，2026-10-16；判法見 §9.6）。建議的判法同 `funnel`：固定點旁 8 格內的格子剩不到一半 ⇒ 那一件壞了；主機壞了 ⇒ 額外動力（`ships[].cfg.base`）歸零、每條煙囪停煙；某一組鍋爐壞了 ⇒ 動力照剩下的鍋爐座數打折、它 `funnel` 那條煙囪停煙。實際規則由遊戲那側定。

- `wheel`／`binnacle`／`capstan`／`boat`／`grating`／`galley` 只說「這是什麼」：站位、血量、能不能放下水、踩不踩得過去這些由遊戲決定，⛔ 不寫進 meta（餘燼號階段十七～二十、憲法號階段四十，2026-10-13 補）。

- meta 是平的 `{鍵: 字串或數字}`，`work sub=model｜link meta=` 合併進去；有 meta 的檔 schema 會升（models 2、links 3），舊 exe 讀不了會大聲擋。
- 梯子的四個點都取「腳踩的那一格」＝ 地板或踏板上面第一格空氣（讀的人取格心）：foot ＝ 下層甲板、最低一階往下梯方向站著等的那一格；lo／hi ＝ 最低／最高那一階；head ＝ 上層甲板、跨過艙口圍欄站穩的那一格（往外第一段連續 3 欄一樣高的平地）。哪兩層甲板由 foot／head 的高度判斷，不另外標。
  算點：餘燼號 `design/tools/ladder_points.py <組裝件> <甲板子作品>:<關聯名>:<梯子子作品>…`（梯名與方向從扶手繩固定點 `manrope-<梯名>-<P|S>-<top|bot>` 讀；不帶 `--apply` 只算）。
- 繩梯（橫繩組 `climb=1`，§6）跟梯子同一套：遊戲把它當一座梯子（第一人稱 E 爬、水手照 §9.3 走）。差別只在踏板是繩 ⇒ 斷不斷照橫繩（斷一半以上 ⇒ 斷了），不看格子。
- 匯出：`op=export format=parts`（外框＋meta＋固定點的 JSON）、`format=vxk include=rig,models,parts,meta`（給遊戲；out 要絕對路徑）。改完任何部件都重匯一次，**格數與 checksum 會變**，要跟遊戲那側說。

### 9.4 匯進遊戲：成品預設壓縮（TASK-0583）

- **造船這側什麼都不用改**：作品與 `format=vxk` 匯出的格式不變；遊戲那側 `admin.py import／reimport` 存的 `_cache/<船>.vxk` 也是原檔（指紋防呆照舊）。
- 遊戲建成品（`admin.py build`，匯入、重新匯入、同步 meta、後台「儲存並重建」都走它）時才壓縮：模型網格收成一個池子 —— **同一份網格不管幾艘船用到只存一次**、頂點去重＋差值；寫出去之前照遊戲的讀法還原、跟原檔逐個比（對不上 ⇒ 不寫）。六艘：成品 9.09 MB → 5.36 MB。
- 量過大小的組成（壓縮後）：格子整艘約 0.1–0.2 MB，**模型網格才是大頭**（憲法號、三叉戟號各約 1 MB）⇒ 對成品大小最有效的是 §2.1「用已有的元件」，不是少雕幾格。
- 原格式 `admin.py build --raw`；`admin.py verify` 把成品跟 `_cache` 原檔比。壓縮版的成品解不回原本的 .vxk ⇒ 遊戲那側 `_cache` 掉了（換機器）走 `admin.py cache`：從雕刻作品重新匯出、跟指紋比（`Blockside/src/README.md`）。
- 📦 遊戲 2026-10-15 起獨立成 **Blockside**（線上 https://tim099.github.io/Blockside/；TASK-0586）—— `admin.py`、`rooms.py`、`decks.py` 都在 `Blockside/src/`，`.vxk` 快取在 `Blockside/VoxelKit/_cache/`。

### 12.1 為什麼：現在的關聯有三種寫法混著用

| 寫法 | 例 | 會壞在哪 |
|---|---|---|
| 照路徑 | 裝甲 `mount=甲板-main/砲塔`、鍋爐 `funnel=煙囪`、彈藥庫 `hoist=梯子/turret`；火藥庫找桶、砲塔巢狀、砲在哪層甲板照路徑前綴 | 改名、換資料夾就斷；改裝船拆掉被指名的部件就斷（§11） |
| 照序號 | 帆腳綁哪根帆桁（footYard）、繩綁哪個模型（遊戲 `linkRopes` 存模型序號） | 中間插一件，後面全部位移 |
| 照位置猜 | 繩端點離哪個模型外框夠近就綁哪個 | 零件一換、一搬就可能綁錯 |

另外 `mount=` 同名兩義：在砲上是砲架種類（`turret`／`pivot`），在裝甲上是「跟著哪門砲」。

### 12.2 物件 id

| 項目 | 規則 |
|---|---|
| 誰有 | 每件關聯（部件）、外部模型。一個關聯裡有好幾座的（梯子、艙房）不另外發號：`<關聯 id>#<座名>`（例 `ladders-1#turret`）。繩、帆先用名字當 id —— 名字在一艘船裡本來就唯一、又不是路徑；橫繩組展開的子繩沒有自己的紀錄，發不了號 |
| 格式 | `<類別>-<序號>`，例 `gun-7`、`oar-12`、`funnel-1`、`ladders-1`、`deck-3`。類別 ＝ meta `kind`（沒有 kind 的關聯 `part`、模型 `model`）；序號只用數字（舷、桅名這些照 meta，不進 id） |
| 寫在哪 | 那一件自己的 meta：`id=gun-7`。是**擺上船的那一次**的 id（同一件砲子作品擺 54 次 ⇒ 54 個 id），不是來源子作品的 |
| 誰發 | Blockside `python -I src/admin.py ids --id <船>`：照部件清單的順序給沒有 id 的發號，用 `sculpture op=work sub=meta` 批次寫回作品（meta 不限作者，每一筆記在那件作品的 `meta_log.jsonl`），再把 id 與指名的鍵同步進 `_cache` 那份 .vxk（⛔ 不走 metasync：別人還沒匯進來的 meta 改動不會被一起帶進來）。下一號記在 Blockside `config/game.json` 的 `ships[].idNext` ⇒ 刪掉的號不重用。新船匯入後、加了部件之後跑一次（已經有 id 的不動） |
| 範圍 | 一艘船（組裝件）裡唯一 |
| 不變 | 改名、換資料夾、挪位置、重匯都不變；複製出來的一件 ⇒ 新號（發號時撞號 ⇒ 後來的那件換新號並報出來） |
| 改裝船 | 原船整艘當一條關聯帶進來 ⇒ 原船的 id 照用；改裝船自己加的用自己的號段：`<改裝船代號>.<類別>-<序號>`（例 `sentinel.gun-1`）⇒ 原船之後加東西也不會撞；原船要先跑過 `ids` |
| 同一件子作品關聯好幾次 | 裡面那幾件是同一筆紀錄 ⇒ 只有一個 id；遊戲照最近一層關聯的 id 分開：`<關聯 id>/<內部 id>`（例：哨兵號兩個彈藥櫃裡的火藥桶） |

### 12.3 關聯的寫法

- 指整件寫 `id`，指那一件上的固定點寫 `id#固定點`（例 `gun-7#breech`、`sail-4#<角名>`）。
- 欄位一覽（舊 ⇒ 新）：

| 誰 | 舊 | 新 |
|---|---|---|
| 裝甲跟著哪門砲 | `mount=<砲的路徑>` | `mount_of=gun-7`（`mount=` 只留給砲架種類） |
| 鍋爐的煙囪 | `funnel=<路徑>` | `funnel=funnel-1` |
| 主機的螺旋槳 | `propeller=<路徑>` | `propeller=propeller-1` |
| 彈藥庫從哪座梯子吊火藥 | `hoist=<梯子路徑>` | `hoist=ladders-1#turret` |
| 帆腳綁哪根帆桁 | 照帆腳那條繩的 `ends` 找帆桁模型（本來就是照名字，查過不是序號） | 不改 |
| 繩的兩端 | 作品的 `ends` 有寫 `model:<模型>/<固定點>`，遊戲卻照外框猜綁哪個模型；模型排在母繩前面 | **匯入時**照同一套規則算好每一端綁在哪、寫進 `.vxk`（`rig.ropes[].bind`），遊戲照它綁、執行時不猜（Blockside `admin.py ropebind`，匯入／重新匯入／metasync／ids 會自己跑，報表 `reports/ropebind_<船>.md`）。順序：砲塔的殼 → 作品寫明的（`model:` 那個模型、`rope:` 只找繩、`sail:` 與固定點不猜模型）→ 帆桁 → 母繩（≤ 3 格）→ 最後才照外框猜模型（報表列出來）。雕刻端檢查：`work sub=ropecheck`（§10）。改寫成 `gun-7#breech` 留到掛點那一段（TASK-0714） |

- 規格表（Blockside `src/config/meta_kinds.json`）每一類登記 `refs`：哪些欄位是關聯、能指哪幾類。
- 匯入檢查：沒有 id ⇒ ⚠；撞號 ⇒ ✗；指到不存在的 id ⇒ ✗；類別不對 ⇒ ✗；`#` 後面那一座不存在 ⇒ ✗；繩端只靠照位置猜才綁上 ⇒ ⚠；舊寫法 ⇒ ⚠。
- 量過（2026-10-18）：作品寫明綁在模型上的繩端 3,048 個，照外框猜錯 98 個 —— 風暴角號 P1 砲的 breeching 綁到 S1 砲、潮墓號 96 條砲尾的繩綁到旁邊的導纜器。改照 `ends` 之後這兩艘的戰局跟著變（修好的）；另外 715 個繩端遊戲先綁船殼的格子（旁邊 5 格內有格），這一條沒改。
- 量過（2026-10-18，TASK-0716）：改成上面的順序之後 17 艘照外框猜的 0 端、哪裡都不靠的 0 端 —— 以前被猜到模型上的 409 端（潮墓號 384、風暴角號 20 …）其實都接在別的繩上或作品寫明了；雕刻端 `ropecheck` 也只找到炎羽號 2 端要挪（20 cm）。

### 12.4 掛點：原本雕的零件 ＝ 可換零件的位子

- 每一件可換零件同時是一個**掛點**：id 不變，只多記「現在裝的是哪一件」。換裝表 `{ "gun-7": "carr" }`（值 ＝ Blockside 砲種表的鍵）。
- **沒換 ⇒ 裝的就是原本雕的那一件**（網格、固定點、meta 都照原本）⇒ 戰局跟沒有這套時逐位元相同。
- 換了 ⇒ 從零件表拿那一件的網格與固定點，照掛點的座標系擺上去；meta 換成那一件的（種類、重量、要幾個人）。站位、重量、家具擋格照新的重算；繩端寫的是 `id#固定點` ⇒ 跟著新零件同名的固定點走。
- 同一類零件要有同一組固定點名字（零件表那一件缺 ⇒ 不收進表）。

| 類 | 座標系（照原零件的固定點） | 能換成 |
|---|---|---|
| 砲（已實作，§12.4.1） | `breech`→`muzzle`、對齊砲口（迴旋砲、旋轉砲座對齊 `pivot`）、外框底 | 同一種砲架（舷側、迴旋砲 `pivot`、旋轉砲座 `turret`） |
| 槳 `kind=oar` | 對齊 `pivot`（三軸）、方向 `pivot`→`blade`；meta `side` 不同 ⇒ 鏡射 | 槳（留掛點的 `side`、`bank`；槳手人數、划幅照零件） |
| 舵 `kind=rudder` | 對齊 `stock-top`（三軸）、不轉 | 舵（`hinge_*` 跟著挪、`axis_*` 跟著轉、`max_deg` 照零件） |
| 螺旋槳 `kind=propeller` | 對齊 `hub`、不轉 | 螺旋槳（`axis_*` 跟著轉） |
| 舵輪 `kind=wheel` | 對齊 `hub-aft`、方向 `hub-aft`→`hub-fore` | 舵輪（`spin_pivot_*`、`spin_axis_*` 跟著挪、轉） |
| 燈 `kind=light` | 對齊 `bail` | 燈（可拆空） |
| 提燈 `lantern`、小艇 `boat`（方向 `ring-aft`→`ring-fwd`）、絞盤 `capstan`、羅經櫃 `binnacle`、舵輪架 `wheel_stand`、格柵 `grating`、裝飾（沒有 kind、`deco=1`） | 兩邊都有的固定點才用；沒有 ⇒ 外框底面中心、照作品的方向 | 同一種（提燈、小艇、格柵、裝飾可拆空） |
| 錨 `kind=anchor`（模型或關聯；第四段 TASK-0793） | 對齊 `ring`（三軸：鐵鍊綁的、掛在吊錨木上的那一點）、方向 `fluke-a`→`fluke-b` | 錨（掛點的 meta `hawse` 留著：錨鏈孔是船殼的座標） |
| 主機 `kind=engine`（自帶格子的模型，§9.6；第四段） | 水平對齊 `core`、高度 ＝ 外框底（坐在同一層地板上）、不轉；對齊點在中線哪一邊跟掛點不同 ⇒ 照中線鏡射 | 主機（掛點的 `propeller` 留著）；管風琴（`engine=organ`，魔法動力源）只換管風琴 |
| 鍋爐 `kind=boiler`（自帶格子的模型；第四段） | 外框底面中心、不轉；中線哪一邊不同 ⇒ 鏡射（⛔ 不對齊 `uptake`：前後兩組共用一個煙道口的船，換進後面那一格的會疊到前面那一組上） | 鍋爐（掛點的 `funnel` 留著：通哪一根煙囪照原本） |

- 兩邊（掛點、零件）都有的固定點才拿來對齊；沒有 `at` 那一點 ⇒ 外框底面中心。
- 換裝表的值（砲以外）：零件表那一件 `"<船 id>#<模型 id>"`（Blockside `config/game.json` `parts.<kind>`，`admin.py parts` 收：每一種 kind 長得不一樣的每一件）；`"*"` ＝ 原本雕的；`""` ＝ 拆空（綁在它上面的繩一起拿掉）。
- meta：照零件的；掛點自己的 `id`、`fits`、`optional`（槳另外留 `side`、`bank`）留著。
- 放得下：長寬高 ≤ 掛點的 ×1.15 ＋ 2 格（跟砲一樣）。meta `fits=<值,…>` ⇒ 只收名單上的（砲寫砲種、其他寫零件的參照）；`optional=1` ＝ 這一件也可以拆空。
- 放不下（外框超過原件太多、類別不合）⇒ 不換、開戰時廣播、匯入檢查報。
- **不當掛點**：帆桁（綁著帆與繩，算帆裝）、火藥桶（火藥庫的存量，走家具那一套）、門與砲門蓋板（跟船殼開口綁死）、導纜器、齒輪、爐灶。
- **主機、鍋爐**（第四段，TASK-0793）：換的是格子。
  - 掛點原本那一塊從船殼拿掉，零件的格子照上表對齊放進去，材質、平滑照零件。
  - 跟船殼或別的主機、鍋爐重疊超過 3% ⇒ 不換。
  - 之後重量、進水、被打、剩幾成全照新的格。
  - 輸出：每具主機都寫了 `ihp` ⇒ 額外動力的全速航速 × ∛(換後 ihp 合計 ÷ 換前)：推力 ∝ 航速²，功率 ∝ 航速³。有一具沒寫 ⇒ 航速照原本，匯入檢查講一聲。
  - 軸、蒸汽管不動：主機照舊接 `fwd` 離 `core` 最近的那根軸，蒸汽管接 `from` 離它最近的那一組鍋爐。
- **錨的關聯**（憲法號、餘燼號、三叉戟號）也是掛點，不用改作品。
  - 遊戲載入時先把關聯拆成模型：那幾格從船殼拿掉，外露的面做成網格。
  - 拆好之後照上表錨那一列換。
  - 量過：憲法號兩錨換成夜燈號、皇家號的 ⇒ `ring` 還在原本那一格、兩爪照原本左右舷；拋下去 9 秒內咬底。
  - 拆出來的那一份只有開局才有 ⇒ 不收進零件表（別艘換不到它）。
- **結構，不動**：船殼、甲板、桅、梯子、艙房、彈藥庫、裝甲。

#### 12.4.1 砲的掛點（已實作，TASK-0714）

造船的人要做到的：每一門砲（`kind=gun`）有 id、有固定點 `breech` 與 `muzzle`；左右舷的砲要分得出是哪一邊 ⇒ 至少有 `eye-aft`、`eye-fwd`、`train`、`cascabel` 其中一個不在砲軸上（一般砲架都有 `eye-aft`／`eye-fwd`）。迴旋砲、旋轉砲座再加 `pivot`。

| 項目 | 規則 |
|---|---|
| 座標系 | 砲軸 ＝ `breech` → `muzzle`（水平）。水平的對齊點：舷側砲架 ＝ `muzzle`（換上去的砲，砲口還在同一個砲門）；`mount=pivot`／`turret` ＝ `pivot`（兩邊都有才用）。高度 ＝ 外框底（砲架放在同一層甲板上） |
| 左右舷 | 零件跟掛點不同邊（`eye-aft` 在砲軸的另一邊）⇒ 照砲軸**鏡射**，不是轉 180°（轉的話船尾那條滑車繩會接到船頭那一邊） |
| 能換成 | 同一種砲架（meta `mount`：沒寫 ＝ 舷側砲架；`pivot` ＝ 迴旋砲；`turret` ＝ 旋轉砲座）。弩砲、投石機、弓、希臘火（砲種表有 `weapon` 的）這一段不換：弦、弓這些繩是那艘船自己的 |
| 放不放得下 | 零件在砲的座標系裡的長、寬、高都 ≤ 掛點的 ×1.15 ＋ 2 格。掛點 meta `fits=<砲種,…>`（砲種表的鍵，例 `fits=long,long32,carr`）⇒ 只收名單上的，不看大小 |
| 繩 | 作品的 `ends` 寫 `model:<這門砲>/<固定點>` 的那一端，照新砲同名的固定點挪（整條照離那一端的長度遞減）、照樣綁在砲上；新砲沒有那個固定點 ⇒ 那條繩拿掉（例：carronade 沒有 `train` ⇒ 沒有後拉滑車）⇒ 同一類砲的固定點名字要一樣 |
| 換不成 | 掛點不在、類別不合、放不下、零件表沒有 ⇒ 照原本雕的那一門；開戰時廣播一行、匯入檢查報 ✗ |
| 甲板在哪 | 照砲猜甲板高度、站人範圍的地方（砲甲板分層、砲班站的高度、陸戰隊的 spar deck）照**原本雕的那一門** —— 甲板是船的事，不跟著換上去的砲走 |

### 12.5 存在哪

| 什麼 | 在哪 |
|---|---|
| id | 作品裡每一件的 meta（雕刻端） |
| 零件表 | Blockside `config/game.json` 的 `parts.guns` ＝ `{ 砲種: { 砲架類別: "<船 id>#<模型 id>" } }`、其他類 `parts.<kind>` ＝ `{ "<船 id>#<模型 id>": 名字 }`（槳、舵…、錨、主機、鍋爐；主機、鍋爐要有 `vox`）：`python -I src/admin.py parts` 照 `_cache` 產生（每一種砲 × 砲架類別取第一門）。只記引用，⛔ 不另存網格（船檔裡本來就有；22 種另存 ~120 KB ＝ 成品 +6%）；遊戲要用時才載那一艘的船檔。這艘自己就有同種同類的砲 ⇒ 用自己的 |
| 出廠換裝表 | Blockside `config/game.json` 的 `ships[].fit` ＝ `{ "gun-7": "carr" }`（值 ＝ 砲種表的鍵） |
| 玩家的換裝表 | 跟船員配置、艙房同一套存檔與匯出匯入（船隻配置頁）；艦隊裡可以寫 `<船型>@<掛點>=<砲種>;…`（網址 `?blue=constitution@gun-2=carr`）⇒ 同一型兩艘換得不一樣，各建一份船型 |
