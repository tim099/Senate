# 🚢 照圖紙雕大型作品 —— 流程、心得、注意事項

> **一句話：不描圖，重新設計一套新圖紙；作品照新圖紙雕；每一階段收兩本帳 —— 作品＝設計、設計＝圖紙。**
> 操作參數看 `senate cmd help sculpture`、指令本身看 [Sculpture](Sculpture.md)，⛔ 本檔不抄參數表。
> 範例作品：`Sculpture/works/basecamp-frigate-constitution-01m/`（0.1 m／格、1024×320×800）——
> 規格與讀數在它的 `notes.md`、心路歷程與參考資料在 `journal/`、過程圖在 `overlays/stageN_*`、新圖紙與產圖程式在 `design/`。

---

## 0. 適用範圍

- 有比例尺、有原圖（或照片、文字規格）可以對照的大型作品：船、建築、機械。
- 精度到「格」級（例如 0.1 m／格），而且要分好幾個階段、好幾天做完。
- ⛔ 小件、自由發揮的雕刻不用這一套 —— 這套的成本在驗證，值得的是「要對得上一張圖」的作品。

## 1. 總流程（每一階段都走一輪）

| # | 步驟 | 產出 | 這一步在防什麼 |
|---|---|---|---|
| 1 | **開單**：委託開一張傘單，每階段一張子單（`epic_id`＝傘單） | 驗收標準：新圖紙／照圖雕／讀數（含反向對照）／過程圖與日記／筆記與 TODO | 球在誰、做到哪；反向對照那一行讓「永遠會過的驗收」現形 |
| 2 | **找圖與校準** | 原圖放 `references/`、校準參數寫進筆記 | 比例尺、旋轉、**拼貼接縫** |
| 3 | **新圖紙**（設計，不描圖） | `plan.json`（參數＋provenance）、產圖程式 → 圖紙、對照圖、遮罩、`verify*.json` | 原圖的手繪起伏與錯位不進作品；每個數字知道從哪來 |
| 4 | **預檢**（貼之前） | 遮罩展開成 voxel：跟現況重疊 0、片與片重疊 0、左右對稱、接頭沒有空欄 | 撞格在動刀前就看得到 |
| 5 | **先貼一片** | 一片落地、切剖面看形狀 | 軸向第一次用時「以為的軸向」 |
| 6 | **迴圈貼完** | 每片讀回 `placed ＝ expect_pixels × thickness`，對不上就停 | 引擎跳過已佔用的格**不報錯** |
| 7 | **結果帳** | 「階段前狀態＋本階段遮罩」推出的應有模型 vs events 重播，逐格比（含顏色） | 作品＝設計 |
| 8 | **結構檢查** | 洞、face-connected 元件數、3D 封閉空腔 | 看不到的錯（內殼、浮空） |
| 9 | **圖紙比對**（從圖紙像素出發） | 圖上畫的格作品全有；作品多的格逐格分類（線條、十字蓋住的） | 設計＝圖紙 |
| 10 | **原圖第三方對照** | 原圖讀數點到作品的距離 | 新圖紙沒有偏離原設計 |
| 11 | **反向對照** | 錨點故意偏 3 格，探針要報 3 | 尺本身會不會說話 |
| 12 | **獨立 verifier**（workflow，多視角、被叫去推翻） | 每個視角 pass／minor | 作者自己的程式量不到的那格 |
| 13 | **修正** | 能補格就補格（新遮罩是舊遮罩的超集）；要刪就精準刻 | 修一格不動到別的格 |
| 14 | **過程圖、日記、筆記、TODO** | `overlays/stageN_*`、`journal/stageN.md`、`notes.md`、`todo.md` | 下一個人（或明天的自己）從哪接 |
| 15 | **簽收與提交** | 驗收格逐格 `check`；`senate cmd commit` 頂格 `Fixes TASK-<n>` | 處置與結果分開結帳 |

⭐ 7 和 9 是**兩本帳**：結果帳只證明「作品＝設計」；設計自己錯了（少一排、兩條規則打架），結果帳照樣全綠。圖紙比對要**從圖紙那一邊**出發。

## 2. 座標與慣例（先寫下來，再動手）

- **格 k 佔 [k, k+1)、中心在 k+0.5。** 所有「在不在線內」「離線多遠」都拿格中心判斷。
- 中線：龍骨 5 格寬（y 158..162）⇒ 連續座標的中線是 **y = 160.5**；`dy = y − 160`，dy=0 那格中心離中線 0。
- 鏡像：y ↔ 320 − y（158↔162、160↔160）。
- 高度：z = 0 是護龍骨底面；原圖若從別的基準量（龍骨頂、水線），換算式寫進筆記。
- 一片 3 格厚的部件用**片中心**判斷形狀時，兩端那幾片最外一欄會凸出曲面（bevel）—— 要不要逐欄判斷，先決定再寫遮罩。
- `x 欄 = round(X) − 1..+1` 跟格中心慣例差半格（平均 +0.49 格）；`floor(X)` 才平均歸零。⇒ **選一個、寫下來、整件作品沿用**（憲法號選了 round，因為底肋已雕、美觀看不出來）。
- 作品比例：書卡 `meters_per_voxel`；剖面與疊圖照它換算。

## 3. 找圖、讀圖、校準

- 公有領域來源（例：NARA RG 19，Use: Unrestricted），檔名與出處寫進筆記與日記。
- **讀圖交給 workflow**：每份讀圖配一個 verifier，任務是**重量並試著推翻**（不是確認）。
  - 給**時間上限**、把要的數字**寫窄**（「哪幾站、哪幾條線、什麼單位」）。
  - verifier 要拿得到原圖，否則它只是讀圖 agent 的回聲。
- 🩸 **拼貼的圖**：02 號側面圖的船頭那張紙用膠帶接過，接縫兩邊差半格；比例尺端點**跨了接縫**，換算出 1 格級的系統誤差 —— 是被叫去推翻的 verifier 抓到的（船身那張 74.31 px/ft 而不是 74.47；位移 31.5／17 px 而不是 24／12）。
- 🩸 **雙線**：11 號 3 號站跟 4 號站同值，疑為雙線 ⇒ 排除並寫進 provenance。
- 同一艘船的不同圖會互相不同意（11 號與 15 號的船底差 1.5 ft）：**選一張當主、另一張當修正**，寫明。
- 原圖只存讀數就好；**讀數檔要存全**（憲法號第一次讀 11 號只存了 1～9 號站橫剖面，後來要做兩頭才發現水線半寬圖畫到 0、10 號站）。

## 4. 新圖紙（設計，不描圖）

- **`plan.json` 是設計來源**：每條線是參數（圓弧、切點、樣條、表格），每個數字在 `provenance` 標三種之一：**原圖讀數**／**參考資料（附出處）**／**設計決定**。
- **產圖程式**（`draft*.py`）一支產出：圖紙 PNG、原圖對照圖、遮罩、`verify*.json`（每片的 `stamp{png, at, facing, thickness, expect_pixels}` 與讀數）。重跑要逐位元組穩定。
- 圖紙缺的部分可參考其他同類船的圖紙、照片、文字資料，由設計者補上（Tim 2026-10-11）；⚠ 只讀到搜尋摘要的資料要標明「沒逐頁讀」。
- **美觀優先、不追求完全復刻**（Tim 2026-10-11）：量測照做、讀數照寫，但「比原圖準半格」這種看不出來的差，不是重做的理由。
- **顏色要少**：同色在匯出時會合併（憲法號 36 萬格 → `export obj merge=greedy` 5.8 萬面）。木紋、分段只留在圖紙上，作品同色。
  🩸 RGB332 的 140 印出來是橄欖黃，不像木頭 —— 選色前先看 `palette_rgb` 的實際 RGB。
- **手排的設定檔不要 `json.dump` 整份重寫**：🩸 一次 dump 把 plan.json 的 diff 弄成 625 行。用文字插入只加那一段，再 `json.load` 驗。
- 圖說要照實列出畫了什麼：🩸 body plan 右半邊疊畫了兩片底肋、圖說只寫一片 ⇒ 驗收的人（作者與一位 verifier 各一次）都以為作品歪了。

## 5. 遮罩與落子

- **軸向規則**（引擎 `SCP_SculptEngine.TryAxis`）：
  | facing | u（圖的欄）→ | v（圖的列）→ | 備註 |
  |---|---|---|---|
  | z± | X | Y | v 翻轉 |
  | y± | X | Z | **不翻轉** ⇒ 遮罩第 0 列是最低的 z（圖看起來上下顛倒，這是對的） |
  | x± | Z | Y | v 翻轉：y = at.y + (H−1−v) |
- 一張遮罩可以多色；alpha < 128 不落地；**一律帶 `expect_pixels`**。
- **先貼一片**、切剖面（`op=section`）看形狀，再迴圈貼完。迴圈每片讀回 `placed`，對不上就停 —— ⛔ 不要「全部貼完再看總數」。
- 作品內落子免費；`share` 在作品落子這條路徑不會被讀（回報會說 unread）。
- 🩸 `carve` 的 stdout 把 `carved_count` 印成 `placed = N` —— 解析回報時先看實際印了什麼，⛔ 不要照 JSON 欄位名猜。

## 6. 驗證

### 6.1 結果帳（作品＝設計）
- 自己寫 events 重播（`box`：`placed_voxels`＋`color`；`carve`：`carved_voxels`；`stampimg`：`placed_colored`），⛔ 不讀引擎的視圖當真相。
- 應有模型 ＝ 階段前狀態 ＋ 本階段遮罩（**照落子順序、跳過已佔用**），跟重播逐格比：缺／多／顏色不同、階段前的格被動到幾格。
- 🩸 重播函式回傳 `(color, event)`：拿整個 tuple 跟顏色比，全部比不到，**檢查空轉、印出空結果而不報錯**。看到「0」先做正向對照（拿確定存在的東西用同一把查詢查一次）。

### 6.2 結構
- 每片每欄沿 z 的段數（船殼彎，一欄穿過肋骨帶兩次是正常的，不要誤判成洞）。
- 6 鄰接連通元件數：整件作品應該是 1。
- **3D 封閉空腔**（`scipy.ndimage.binary_fill_holes`）：🩸 雙肋貼齊下一站底肋時，keelson 底下中線那一格被四面封死，5 個、300 格 —— 從哪個角度都看不到，匯出卻多一層內殼；填成同色 chock 之後面數反而少了。
- 薄帶的單格針孔：🩸 舷頂附近 moulded 只剩 1.85 格，最近頂點取樣漏掉夾在中間的格（64 個）。

### 6.3 圖紙比對（設計＝圖紙）—— 探針從被量的那一邊取
- 🩸 **假證人**：探針點從**遮罩**挑、再換成圖紙像素 ⇒ 問作品「那格有沒有 voxel」永遠是有，等於沒量圖紙。疊圖目視才發現不對。
- ✅ 做法：從**圖紙像素**出發逐格問「圖上這格是不是畫成部件色？作品這格有沒有？」；作品有、圖上不是部件色的格，**逐格看像素顏色分類**（紅線、黑線、十字、反鋸齒混色）—— 分類完沒有剩，才算 0 差。
- 圖紙畫在上面的疊層（紅線、十字）會蓋住格子：那些格要分類，⛔ 不要放寬容差讓它們「變成木頭色」。

### 6.4 反向對照
- 錨點故意偏 3 格，探針要報 3。報 0 的尺是瞎的。
- 🩸 報出 2 的時候**先問是尺還是手**：探針放在頂格往下 0.6 格處，偏 3 之後只剩 2.4 格 ⇒ 改放頂格中心，7 根全報 3。
- 探針旁邊有別的部件（相鄰肋骨的投影）時，偏移後先找到的是它 —— 反向對照挑「旁邊沒有東西」的點。

### 6.5 原圖第三方對照
- 拿**原圖讀數點**（不是自己的遮罩）量到作品的距離：憲法號船中底肋 vs 15 號 molded 點 ≤ 0.73 格、肋骨內面 vs 15 號內面 ≤ 0.48 格。
- 讀數點落在部件範圍外（例如超過底肋頭）時，報的距離是到端點的距離，不是偏差 —— 分開寫。

### 6.6 獨立 verifier（workflow）
- 3～4 個視角：**帳與結構**、**照設計參數重算幾何**、**從圖紙像素量**、（需要時）**接合與連通**。
- 規則：唯讀（⛔ stampimg／box／carve／work update…）、輸出只寫在自己的資料夾、**不准 import 作者的檢查程式**（可以 import 作品的設計模組，但要說明靠了哪裡）、時間上限、拿不到讀數的寫 unverified。
- 它們會找到作者自己量不到的：🩸 底肋中心系統性偏半格（作品與圖紙同一支程式產，一起偏，疊圖永遠對得上）；🩸 迴圈上限少一排（`range(8, floor(top))` 讓 `zc > top` 那行成了死碼，結果帳因為「作品＝設計」照樣全綠）。

## 7. 修正：補格 vs 精準刻

- **補格**（優先）：改產圖程式讓新遮罩是舊遮罩的**超集** ⇒ 重貼只落地缺的格；每片預期 `placed ＝ (新 − 舊) × thickness`。全部遮罩都已落地的片不要重貼（全被佔用會被擋）。
- **精準刻**：要刪的格先拆成盒子，**每個盒子事先驗過只含要刪的格**（`carve` 的 AABB 會刪掉盒子裡所有東西），再刻、再補。🩸 底肋凸進 keelson 的 180 格：58 個盒子刻掉、keelson 重貼補回 180。
- 不是每個不一致都要消滅：🩸 25 格邊界格留給底肋 —— 讓了會留洞。選一邊、寫下來為什麼。
- 修完**重跑全部讀數**（帳、結構、圖紙、反向對照、匯出面數），⛔ 不要只重跑出事的那一項。

## 8. 過程圖、日記、筆記

- 過程圖存 `overlays/stageN_<內容>.png`：第一片試貼的剖面、疊新圖紙、反向對照、原圖對照、3D（全景、側面、船內、兩頭）。修正前後的示意圖也存。
- **日記** `journal/`（Markdown，相對路徑連圖）：做的時候在想什麼、哪裡停下來、怎麼發現的；查到的參考資料與參考圖（網址、拿來決定了什麼）也記在這裡。規格與讀數仍以 `notes.md` 為正本。
- `notes.md`：每階段一節（設計、雕刻表、讀數、已知偏差＋為什麼留著）；`todo.md`：下一步從哪接、⚠ 下一階段會撞到的東西（例：鋪外板前要先處理 bevel 凸出的格）。
- 範圍決定（委託人說的「不做什麼」「怎麼做」）寫進筆記開頭與傘單留言，⛔ 不只留在對話裡。

## 9. 提交

- 照 `scp-commit`：先 `auto-commit` 收機器檔 → **用檔案清單具名 stage**（`git add --pathspec-from-file`）→ `senate cmd commit --arg expect_files=<數過的數>`。
- ⛔ `__pycache__` 不收。
- 頂格 `Fixes TASK-<n>`，每張都要真的做完（驗收格逐格簽過）。
- 🩸 events 很大：憲法號階段四＋五一筆 commit 新增約 193 萬行（每一刀都逐格記落地的 voxel）。
- 只提交作品那一層；回報時寫明「父層還指著舊 hash」。

## 10. 環境與工具的坑（Windows）

- `print` 中文／符號報 `cp950` 錯：`python -I` 會忽略 `PYTHONIOENCODING` ⇒ 用 `python -I -X utf8`。
- 微軟正黑體沒有 `−`（U+2212）、`⇒` ⇒ 圖上標字用一般字元。
- heredoc 裡的反斜線會被吃掉／變成真換行：長內容用 Write 工具寫檔，⛔ 不經過 shell。
- 一支腳本跑到一半停了（解析失敗）時，先看**已經落地了幾刀**再續跑（帶「從第 N 個開始」的參數），⛔ 不要整支重跑。
