# ⛵ 造船規格與做法（從憲法號整理）

> **一句話：船殼雕成格子；會重複的、會動的、遊戲要認的東西做成子作品，用關聯或外部模型引用，帶固定點與 meta。**
> 通用流程（新圖紙、兩本帳、反向對照）看 [Sculpture_Blueprint_Build](Sculpture_Blueprint_Build.md)；參數看 `senate cmd help sculpture`，⛔ 本檔不抄參數表。
> 範例作品：`Sculpture/works/basecamp-frigate-constitution-01m/`（船殼）＋ `…-assembly`（組裝件）。每一條的出處是它 `notes.md` 的那一段（下面寫「階段 N」）。

## 造船skill入口

造船是雕刻的一種。這一節只告訴你**該讀哪幾份文件**，全部都用 CLI 讀；操作方法以文件和 `help` 為準，⛔ skill 裡不抄。

| 順序 | 讀什麼 | CLI |
|---|---|---|

| 2 | 本檔：船才有的規格、建造順序、砲／帆桁／繩／帆／彈藥庫、給遊戲的 meta、換船檢查表 | `senate cmd doc --arg op=show --arg name=Sculpture_Shipbuilding` |
| 3 | 照圖紙雕大型作品的通用流程：新圖紙、遮罩、兩本帳、反向對照 | `senate cmd doc --arg op=show --arg name=Sculpture_Blueprint_Build` |
| 4 | 雕刻指令本身：op、參數、觀測、關聯、外部模型、繩、帆、匯出 | 先跑 `senate cmd help sculpture`，再跑 `senate cmd doc --arg op=show --arg name=Sculpture` |

- 續造一艘船時，先依第 1 份的續作規則，用 CLI 讀那件作品的書卡、心得和 TODO，再開工。
- 範例船：憲法號 `basecamp-frigate-constitution-01m`（從龍骨照圖紙造），餘燼號 `basecamp-ember-01m`（從憲法號魔改）。產生程式在各自作品的 `design/` 底下。
- ⭐ **儘量用已有的元件**（Tim 2026-10-14）：砲、火藥桶、救生艇、舵輪、羅經櫃、絞盤、燈、格柵這類功能元件，別的船已經做過的就直接當外部模型引用（大小不合可以縮放），⛔ 不要重做一份 —— 比例、固定點、meta 都對過了；匯進遊戲時同一份網格也只存一次（§9.4）。船首像、船尾雕飾這種船的個性裝飾不在此限。現有元件看第 2 份 §2.1；**查不到的砲種或裝備 ⇒ 做成新的通用部件**、遊戲不認得的砲種代碼自己加進砲種表（Tim 2026-10-18，第 2 份 §2.2）。
- 給遊戲標的東西（帆、繩、旗的 meta，空艙房，甲板與梯子，**舵與舵輪跟著轉向轉** §9.8.1）在第 2 份 §9；標完照 §10 檢查表逐條勾。
- ⭐ **匯進遊戲之前跑 `work sub=ropecheck`**（繩端綁定檢查，TASK-0716；用法在第 4 份「繩端綁定檢查」）：寫成座標的繩端遊戲只能猜 ⇒ 報表裡 bind／snap 用 `fix=1` 改、odd／manual 自己看。
- 現有的 op 不夠用時，照第 1 份最後一條，擴充引擎。

## 0. 適用範圍

- 風帆船這一類：有船殼、甲板、桅檣索具、砲，要給人看也要給遊戲用（ame《憲法號對轟》讀 `.vxk`）。
- 本檔記**船才有的**規格與數值；換一艘船時先讀這份，再從憲法號的 `design/` 複製產生程式改參數。
- ⚠ 這裡的數字是憲法號（0.1 m／格、1024×320×800）量到的，換比例或換船要重量，⛔ 不要直接抄。

## 1. 座標、比例、方向（先寫下來再動手）

| 項目 | 憲法號的約定 | 坑 |
|---|---|---|
| 軸 | X 船長、船頭朝 +X；Y 船寬、中線 y=160；Z 高度，z=0 ＝ 護龍骨底面 | — |
| 舷 | P（左舷）＝ y < 160、S（右舷）＝ y > 160 | 從船尾看，引擎視圖觀者的左手邊是 −y（階段十四船名第一次落反）|
| 鏡像 | 格 y ↔ 320 − y（160 那一格是自己）；一舷子作品的另一舷關聯 mirror=y、**at.y ＝ 321 − at.y − 高** | 關聯翻面在自己的框裡翻；外部模型繞 pivot 翻 ⇒ 兩者的 at 換算不一樣（階段三十一：關聯換模型，P 舷 at.y ＋ 32）|
| 比例 | `meters_per_voxel` 0.1 —— **組裝件和每件子作品都要記** | 組裝件沒記 ⇒ 預設 1 m ＝ 32 格，帆的重力與風大了 3.2 倍（掛帆試試）；沒記的作品當模型來源時 scale 自動換算會錯 ⇒ **模型一律明寫 scale** |
| 固定點 | 只收整數格（點取格心）、而且要在作品框裡 | 柱頂、繩端要用「那一格」，框不夠就放大框（階段三十）|
| 繩端點 | 整數 ＝ 格心；帶小數照原值 | 要精準就一律寫小數（階段二十二先拿一條量過：100 → 100.5、110.25 → 110.25）|

## 2. 作品怎麼拆

- **名稱**（Tim 2026-10-14）：組裝件 ＝ 成品，名稱直接用船名（例「憲法號」），不帶 `sub`（主作品，作品下拉列的是它）；船殼名稱「<船名> 船殼」、帶 `tags=sub`。其他部件「<船名> <部件>」。ID：船殼 `<作者>-<船>-01m`、組裝件 `<船殼 id>-assembly`。
- **船殼**＝任務作品（委託、薪水掛在它；組裝件與子作品的 `parent_work` 都指它）：龍骨、肋骨、外板、內板、砲門、舷牆、船尾窗。
- **組裝件**：一開始就建（船殼開工就建、關聯船殼 at 0,0,0）。一格都不雕，只有關聯（船殼、各層甲板、桅、船頭像、channels…）；整件的部件 at 0,0,0，一舷的部件照自己的固定框 at（channels 150,161,70、它的鏡像 150,80,70）；之後加的外部模型、繩、帆、風都掛在組裝件（階段「組裝件與子作品」）。
- **預覽 preset**：組裝件存幾組（`work sub=preset`，見 `Sculpture.md` §9.4.4）—— 藏船殼看裡面、剖半、只看某一層甲板…；Tim 在觀測頁「預覽 preset」下拉切換檢查完工的部分。加了新部件就補一組。
- **子作品**：`parent_work` 掛在船殼或所在的甲板底下（免費、不另領薪），建立時帶 `tags=sub`；房間掛在各自的甲板下 ⇒ 藏甲板會一起藏。
- **左右對稱的東西只做一舷**（固定框，例如 `-head-side` at 630,161,70），另一舷用 mirror=y 關聯；鏡像不要套在整層甲板上，只用在上面的物件（Tim 2026-10-11）。
- **重複的東西做一次**：一門砲、一隻錨、一個火藥桶、一個舵輪各一件子作品，引用很多次。**跨船也一樣**：別的船做過的元件直接引用（§2.1）。
- **會動的、遊戲要個別處理的** ⇒ 外部模型（不是關聯）：砲、帆桁、舵輪、火藥桶。理由：模型可以任意角度轉（關聯只有 90° 的 turn）、可以帶 meta、遊戲拿得到每一個的路徑與固定點。

### 2.1 儘量用已有的元件（Tim 2026-10-14）

開新船先查現有元件，有的就引用（`work sub=model` 的來源指那件作品），⛔ 不要另做一份長得一樣的。清單用指令查（⛔ 不寫死在這裡 —— 元件一直在加）：

```bash
senate cmd sculpture --arg op=work --arg sub=components                 # 全部：被當模型用的作品，引用最多的在前
senate cmd sculpture --arg op=work --arg sub=components --arg kind=gun  # 只看砲（boat、wheel、binnacle、capstan、light、powder…）；kind=gun:24l 只看那一種
```

每一行：來源作品 ID、名字、作者、一格幾公尺、meta（`kind` 與子種類，例 `gun:24l`、`boat:cutter`）、引用幾次與哪幾件作品（看得出哪幾艘船在用）、用過的 scale。
用法：挑一件 ⇒ `work sub=model` 的來源指它、meta 照那一行（同一種東西 meta 一樣，遊戲才認得）；它的固定點看來源作品（`work sub=anchors`）。

- 為什麼（除了省工）：遊戲成品裡**同一份網格只存一次**（§9.4）。2026-10-14 量：六艘的模型網格 161 種，跨船共用的 53 種 —— 24 磅長砲四艘共用、carronade 與火藥桶三艘、舵輪／羅經櫃／絞盤三艘、6 磅砲兩艘；每多一種新網格，成品就多一份（一門砲的網格原始約 20–30 KB；一整艘船自己的網格壓縮後可到 1 MB）。
- **大小不合就縮放**：外部模型的 `scale` 收一個數或 `x,y,z`（`work sub=model`，見 `senate cmd help sculpture`）—— 舵、小艇、絞盤這類照船的大小縮一縮就能用；縮放繞 `pivot`，固定點跟著縮。⚠ 縮過的在遊戲裡是另一份網格（省的是造的工夫，不是成品大小）；遊戲照 meta 認的長度（例 `boat` 的 `length_m`）縮了要跟著改。
- ⚠ 只差一點也是新的一份：改過幾格、換了 scale、換了來源版本 ⇒ 遊戲裡是另一份網格。同一個元件的不同擺法（P 舷鏡像、rotate 180）本來就各一份（憲法號的 24 磅砲兩舷各一份、carronade 四份）。
- **不用複用的**：船首像、船尾雕飾、船名板、旗這種船的個性裝飾 —— 每艘船自己做（Tim 2026-10-14）。
- 真的要不一樣（例如三叉戟號的三管砲、風暴角號的追擊砲）才做新的；做成外部模型來源、帶 meta，下一艘船查得到 —— 怎麼做照 §2.2。

### 2.2 缺的砲種或裝備：做成新的通用部件（Tim 2026-10-18）

Tim 2026-10-18：「有缺的炮種或裝備 就加成新的通用部件吧」。`sub=components` 查不到那一種（kind 或子種類），或現有的跟史料差太多（固定砲架 vs 叉架上的迴旋砲、有橫桿的錨 vs 四爪錨）⇒ **做一件新的通用部件**，⛔ 不要只為這艘船雕進船殼或甲板的格子裡 —— 雕進格子的下一艘船拿不到、遊戲也認不得。
只差大小、口徑差一點的（36 磅 vs 32 磅、8 磅 vs 6 磅）照 §2.1 縮放現有的，⛔ 不另做。

| 項目 | 規定 | 為什麼 |
|---|---|---|
| 作品 | 一件子作品、`tags=sub`、`parent_work` 掛在現在這艘船的船殼（免費、不另領薪）；ID `<船殼 id>-<kind>-<名>`（例 `apex-one-reale-01m-gun-pierrier`） | 一件就是一份網格（§9.4）；跟船的格子分開 ⇒ 誰都能當模型來源 |
| 名稱 | 寫成通用的：「<東西>（<子種類>，通用部件，<一格幾公尺>）」，⛔ 不寫「<船名> 的…」 | `sub=components` 列的是名字；下一個造船的人照名字挑 |
| 比例 | 小件 0.05 m（模型 scale 0.5 明寫）、更小的 0.02 m（scale 0.2）；書卡記 `meters_per_voxel` | §1：沒記的作品當模型來源時 scale 自動換算會錯 |
| 座標 | 照同一種東西的慣例：砲照 §4.1（x 中線、砲口朝 +y、z 0 ＝ 站的那一面）；錨照憲法號的錨（錨幹沿 +z、ring 在上）；門照 §9.7 | ⛔ 自己發明擺法 ⇒ 每個引用的人都要重算 rotate |
| 固定點 | 照 §9 kind 表那一列登記（砲 `muzzle`（內膛空格）／`breech`／`cascabel`，會轉的加 `pivot`；錨 `ring`／`crown`／`fluke-a／b`；門 `hinge-a／b`…） | 遊戲與繩照固定點找；缺 ⇒ 匯入檢查報 |
| meta | 照 §9 kind 表；同一種東西 meta 一樣（`kind=gun, gun=<代碼>`、`kind=anchor, anchor=…`） | 遊戲照 meta 認，不看名字 |
| 產生程式 | 放在做它的那艘船的 `design/`，檔頭寫「通用部件」；格數、框、固定點寫進那艘船的 notes | 要改的人找得到來源 |
| 量 | 零件 1 元件、空腔 0；在自己的船上照 §4.2 退到零碰撞（格心＋八角）、砲口射線不碰到自己的船 | 下一艘船引用時只剩擺法要量 |

- **不是大砲的武器做成「換皮大砲」**（Tim 2026-10-18：「弩炮目前我想直接做成換皮大炮(只是彈藥不同) 一樣走裝彈 發射流程」「弩炮可以給一定的轉動空間(參考維吉尼亞號的前後炮)」）：
  照砲的規格做元件（§4.1 座標、`muzzle`／`breech`／`pivot`），模型 meta `kind=gun, gun=<砲種表的代碼>, weapon=<武器種類>, ammo=<彈種>`；遊戲砲種表要有那一種（缺的照上一條自己加）。
  走同一套裝填、送藥、發射；彈種照砲種表的 `ammo`（固定彈種 ⇒ 換彈鍵換不到它；只有主武器的彈種能換）。要轉 ⇒ `mount=pivot, ports=0,±N`（§4.5，**每個停靠角度都量零碰撞**）。
  持火號：弩砲 `gun=ballista, weapon=toxoballistra, ammo=firebolt`（彈種火箭：照弩箭飛、畫成一支帶火的箭、沒有砲煙，碰到船那一點著火，見下面「彈種」）、船頭 `ports=0,35,-35`（±40 擦到艏樓欄杆 9 格）、木塔 `ports=0,45,-45`；
  siphon `gun=siphon, ammo=greekfire`；投石機 `gun=mangonel, weapon=manganikon, ammo=stone, mount=turret, arc=-180,180`（整圈轉：船頭對敵的船只給兩舷 `ports=0,180` ⇒ 120 秒只對得到 6.5 秒、一發都沒開；每 30° 量零碰撞）。
  - **砲種表的通用鍵**（Blockside `src/config/game.json` 的 `guns`；Tim 2026-10-18）—— 不寫 ⇒ 跟大砲一樣，別的船戰局一個值都不變：
    | 鍵 | 意思 | 例 |
    |---|---|---|
    | `ammo` | 固定彈種：`greekfire`、`bolt`（弩箭）、`firebolt`（火箭）、`stone`（石彈）；沒寫 ⇒ 實心／爆裂／鏈彈輪流 | 弩砲 `firebolt`、投石機 `stone` |
    | `box` | 彈藥量倍率（Tim：「跟共用的是乘數關係(弩炮設定三倍彈藥的話 就是裝填一次可以發射六發 但不是連射)」）：砲旁藥箱裝 `lim.box`（遊戲設定，預設 2）× `box` 發；送藥手一趟補一份 ＝ `box` 發。每發照樣走裝填時間 ⇒ 不是連射（連射是 `burst`） | 弩砲 `3` ⇒ 一箱 6 發 |
    | `elev` | 最大仰角（度）；沒寫 ＝ 15°（大砲的砲門）。射程照 min(elev, 45°) 算 | 投石機 `75` |

## 3. 建議的建造順序（憲法號實際順序，加上事後才知道該早做的）

1. 龍骨 → 艏柱／艉柱 → apron、內艉柱、deadwood → 線形圖 → 底肋＋keelson → 肋骨 → 船頭船尾骨架（每階段一張新圖紙）
2. 外板與塗裝（dubbing、wales、銅／黑／白帶）→ 開砲門 → 船殼內部（內板、clamps、斜肋）
3. 甲板（每層一件子作品；橫樑照「每個砲門底下一根、兩個砲門之間一根」）→ 房間 → 舷牆與舷弧起翹
4. 桅（每根一件子作品）→ 船尾窗與裝飾 → 船頭（knee、billethead、rails、cathead）
5. 舵 → channels → 靜索 → 甲板繫繩點（fife rails、pin rails）→ 帆
6. 砲 → 砲具與砲索 → ratlines → 梯子 → 錨 → deadeyes／lanyards → 舵輪 → 上甲板砲門與 carronade → entry port
7. 彈藥庫與火藥桶 → 給遊戲的 meta

⭐ **事後才知道該一開始就這樣做的**（新船直接照做）：
- **砲一開始就做成外部模型**（階段二十的砲是關聯，階段三十一才換成模型、140 條砲索重綁）。
- **帆桁一開始就是一根一件子作品＋模型**（階段十六把帆桁貼進桅、階段二十六用格子轉角度、階段三十三才拆成模型、刻掉 18,638 格）。
- **組裝件一建立就記 meters_per_voxel**。
- **上甲板砲門跟 channels 一起規劃**：階段二十九開砲門之後，channels 的 deadeye 與 shroud 擋在砲門前面，要整排重擠（channels v2）。
- **甲板高度先照砲門定**：砲門下緣離甲板 6–9 格、clamp 在砲門上緣之上（階段九）。

## 4. 砲

### 4.1 一門砲一件子作品
- 座標：**x 沿船長（砲軸在 x 中線）、y ＝ 砲口方向、z 0 ＝ 甲板面那一層**（階段二十 -gun-24：15×32×16、軸在 x 7）。
- 比例：0.1 m 的砲身看不出台階；第二批改 **0.05 m**（-gun-long18、-gun-carronade32），模型 scale 0.5 明寫（階段二十八）。火藥桶 0.02 m、scale 0.2。
- 形狀要選「在格子上會換形狀」的半徑（base ring、reinforce、chase、muzzle swell 才看得出台階）。
- 🩸 草稿期間改過的（每一次都是渲出來才看到）：base ring r 2.9 ⇒ 5×5 方塊、從後面看像黑磚 ⇒ 2.6；輪子兩格厚像黑球 ⇒ 一格厚＋輪軸頭；砲架 164 渲出來偏亮橘紅 ⇒ 132。
- 色：砲管黑 36、砲架 132、quoin 136（階段二十）；carronade、long18 同一套。

### 4.2 擺上船（外部模型）
- 模型掛在**所在甲板的子作品**上（`甲板-gun/砲-S01`），藏甲板就一起藏。
- S 舷照原樣；P 舷：carronade 用 rotate 180（pivot 在 skid 前緣）；從關聯換過來的長砲用 mirror=y、at.y ＋ 32（§1）。
- **退到零碰撞**：每個砲門從舷牆外面往裡退，直到「模型每一格的格心＋八個角都不在組裝件的實心格裡」，再要求砲口在船殼外（階段二十八／二十九；對「草稿套上去」的組裝件量）。
- 船頭追擊砲：兩舷的長砲在船頭會在中線撞（半寬約 30 格、砲連砲架 32 格）⇒ 不能正橫放；**照角度搜**（憲法號：往船頭偏 5–20° 推得出去、25° 砲口出不了砲門、30° 以上塞不進去 ⇒ 取 −20°）。另一舷用 mirror=y 對 y 321 鏡（`chase18-P`）。
- 砲口伸出：carronade 推到前端時，砲口要超出 skid 前端到夠伸出牆（牆 0.45 m 厚，砲口只超出 0.35 m ⇒ 縮在牆裡；改 0.55 m）。
- **後座**（模型 meta `recoil`；Tim 2026-10-20「是否可以讓沒有炮門的炮 也有後座力呢」「要注意排除弩炮 投石機等(要根據meta判斷)」）：遊戲照砲軸往船裡退、裝填快好再推出去（Blockside `62_ports.js` recoilDist；只是畫面，跟砲門蓋板同一個畫質項）。
  退幾格照這個順序：模型 meta `recoil=<格>`（`0` ＝ 不演）⇒ 固定彈種（meta `ammo`，沒寫照 `weapon`／`gun` 對到的砲種表）是弩箭、火箭、石彈、希臘火 ⇒ 不演（沒有火藥）⇒ 有蓋板 ⇒ 它的 `house` ⇒ 砲管長（`muzzle` → `breech`）× 0.3、至少 4 格。
  ⇒ 一般的砲不用寫；**機械武器照 §2.2 標 `ammo`／`weapon` 就自動不演**；只有預設不對的那一門才寫 `recoil`（例：砲退下去會撞到後面的東西 ⇒ 寫小一點）。匯入檢查「後座」那一行列出每艘幾門、退幾格、哪幾門不演。
- 迴旋砲的砲門（§4.5，`ports` 好幾個角度）：遊戲換砲門時砲會轉過**中間的角度** ⇒ 兩個砲門中間的舷牆柱要拿掉，連成一個口子（蘇士奎哈納號 `design/draft_pivot_sweep.py`：相鄰兩個角度之間每 2.5° 照刻砲門同一條規則再刻，刻完每個角度量零碰撞；Tim 2026-10-20「中間的竿子在砲旋轉時會穿透 應該可以移除」）。

### 4.5 迴旋砲與砲塔（模型 meta `mount`；TASK-0626）

| meta | 值 | 意思 |
|---|---|---|
| `mount` | `pivot`／`turret` | pivot ＝ 在幾個砲門之間換；turret ＝ 連續轉 |

| `fire` | `-174,174` | turret 能開砲的角度（度，選填；沒寫 ＝ `arc`）。砲口不在這個範圍裡就不開，目標落在外面 ⇒ 停在近的那一端等。轉得過去、但朝那邊開會打到自己（駕駛塔、煙囪）⇒ 寫 `fire`，`arc` 照樣一整圈（Tim 2026-10-16：「開火角度跟旋轉要分開(可以預設同一組 但可以額外設定開火角度)」） |
| `rate` | 數字 | 轉速（度／秒；pivot 預設 12、turret 20） |
| `cone` | 數字 | turret 砲管的射界（度，預設 4；pivot 照砲門 ±26°） |
| `pivot` | 數字 | 轉的中心 ＝ 從 `breech` 沿砲軸量幾格（負 ＝ 往後）；模型有固定點 `pivot` 就用固定點（砲塔用這個）；都沒有 ⇒ 外框中心 |
| `runin` | 數字 | 換砲門前先沿砲軸往後拉幾格、轉完再推出去（史料：先把砲拉進來才換）；轉的途中不能開 |

- 跟著轉的：模型、砲軸、砲口、砲班的站位與站著的人、放藥箱的位置；⛔ 模型的外框（被打中、碰撞）不轉。

### 4.6 整座轉的砲塔怎麼做（砲塔艦：莫尼特號這一類）

遊戲轉的是**一個砲模型**（`mount=turret`；Blockside `21_gunnery.js` `gunMountInit`／`mountStep`）⇒ 要整座一起轉的東西（裝甲圓筒、頂、砲、砲架）**做成同一件元件、當一個外部模型**放上甲板。⛔ 圓筒雕在船殼的格子裡、只讓砲轉 ⇒ 砲門不跟著轉，砲口一轉就對著牆。

| 步驟 | 做法 | 為什麼（遊戲那側照什麼讀） |
|---|---|---|
| 1. 元件 | 一件子作品（`<船> 砲塔`，`tags=sub`），比例照砲（0.05 m、模型 scale 0.5 明寫）；座標照 §4.1：y ＝ 靜止時的砲口方向、z 0 ＝ 甲板面上第一格。**框做成正方形、圓心落在一格的中心**（奇數邊長，例 133×133：圓心格 66） | 模型的外框（被打中、碰撞）**不轉** ⇒ 框以轉軸為中心、近似圓 ⇒ 轉到哪個角度外框都還包得住 |
| 2. 固定點（元件裡登記） | `pivot` ＝ 圓心那一格（z 0）；`muzzle`、`breech` ＝ 其中一門的砲口內膛那一格與砲尾（定砲軸，要水平）；每一根砲管 `muzzle-a`、`muzzle-b`… | 轉的中心：模型有固定點 `pivot` 就用它（優先於 meta `pivot` 與外框中心）。⚠ 多根砲管只在**連發**時輪流出彈（砲種表 `burst` > 1）；`burst` 1 的砲種每一發都從 `muzzle-a` 出 |
| 3. 放上船 | 模型掛在**所在甲板的子作品**上；`pivot` ＝ 元件圓心格的底面中心（例 `66.5,66.5,0`）、`at` ＝ 甲板上的圓心（z ＝ 甲板走路格的底面）、`rotate=0,0,θ` 定靜止方向 | 靜止方向就是 `arc` 的 0°：射不到的那一段（駕駛塔、煙囪那一側）放在 ±180° ⇒ 例：靜止朝船尾、`arc=-165,165` ＝ 正前方 ±15° 不打 |
| 4. meta | `kind=gun`、`gun=<砲種代碼>`、`mount=turret`、`arc`、（選填）`fire`、`rate`（度／秒）、可選 `cone` | **代碼要在遊戲的砲種表裡**（`Blockside/src/config/game.json` `guns`）：不認得 ⇒ 默默當 24 磅長砲、匯入檢查報 ✗。砲種表沒有那一種 ⇒ 照 §2.2 自己加（初速、裝填、砲班、重量、每發傷害） |
| 5. 甲板 | 砲塔底下的甲板格**照常鋪滿**（元件不用做地板）；艙口要開就開在轉軸附近 | 砲班站在甲板的格子上，轉的時候站位跟人一起繞 `pivot` 轉；模型的「腳」＝ 外框中心正下方那一格甲板 ⇒ 那格被打掉，整座砲塔掉下去。⚠ 砲班的站位照**模型外框往外**排、站位與走路格避開每個模型的外框（`40_crew.js` `blocked`）⇒ 圓筒放在模型裡 ⇒ 人站在圓筒外的甲板上（2026-10-15 莫尼特號第一版）；**圓筒改成 §4.7 的裝甲 ⇒ 模型外框只包砲、人站得進圓筒裡**（2026-10-16） |
| 6. 量 | ① 掃過的圓（半徑 ＝ 外徑 × scale ＋ 1 格）裡、甲板面以上不能有別的實心（駕駛塔、煙囪、通風口）⇒ 轉一整圈都不穿模；② 每根砲管的 `muzzle` 是空格（內膛）、砲口在圓筒外緣以內一兩格（砲門裡） | 砲塔是連續轉，⛔ 不像 pivot 只停幾個角度 ⇒ 量整個圓，不是量幾個角度 |

- **元件拆三件**（換做法不用重雕）：`-turret-gun`（一門砲＋砲架，用**砲塔的框**、固定點 `pivot` 在圓心）、`-turret-shell`（圓筒＋頂）、`-turret`（一格都不雕：關聯 shell、gun、gun `mirror=x`，固定點 `pivot`／`muzzle-a`／`muzzle-b`…）。上船掛 `-turret` 一個模型；遊戲那側若改成「每門砲各一個模型、圓筒跟著轉」，砲直接改掛 `-turret-gun`（第二門 `mirror=x`）—— 兩門 `pivot` 同一點、`arc`／`rate` 一樣 ⇒ 轉的角度一模一樣（`mountStep` 照同一個瞄準點算）。
- 取捨：外部模型**不吃 material**（§9.5）⇒ 圓筒放在模型裡就是一個血量、打到歸零整座飛出去 ⇒ **圓筒改用 §4.7 的裝甲子模組**（逐格打掉、吃鐵），模型只放砲。
- 火藥：取用點在**砲所在的那一層甲板**（9×9 格平地、頭上 8 格空、不碰砲）、藥箱放在砲尾後面往中線 0.7 m ⇒ 砲塔裡砲尾後面要有站得住的甲板（會跟著轉）；彈藥庫在哪一層都可以，但要有桶（§8）。砲甲板是露天的 ⇒ 用 §8 的 `hoist` 讓火藥從艙口吊上來。
- 實例：莫尼特號（meadow，`meadow-monitor-01m-turret`，2026-10-15）：元件 133×133×60（0.05 m）、圓心格 66、`pivot` 66.5,66.5,0、at 甲板圓心、rotate 90（靜止朝船尾）、`arc=-180,180`、`fire=-174,174`（Ericsson：轉離中線 6° 才過得了駕駛塔 ⇒ 朝駕駛塔那 12° 不開、但轉得過去；2026-10-16 以前寫成 `arc=-174,174`，轉向會繞遠路）、`rate=16`（一圈 22.5 秒）；掃過的圓裡甲板以上別的實心 0。2026-10-16 起元件只剩兩門砲、圓筒與頂是 §4.7 的裝甲子模組。

### 4.7 跟著砲轉的裝甲子模組（關聯 meta `kind=armor`；TASK-0631）

Tim 2026-10-16：「是否可以讓砲可以帶動額外裝甲(子模組) 然後把莫尼特號的砲塔作為子模組掛在砲上 支援體素破壞並且設定為金屬材質」。

| 步驟 | 做法 | 為什麼（遊戲那側照什麼讀；Blockside `24_armor.js`） |
|---|---|---|
| 1. 子作品 | 裝甲（圓筒、頂…）各一件子作品，**用船的比例**（0.1 m）、靜止時的樣子；**框收緊到那幾格的外框**、關聯 `at` ＝ 框的原點 | 遊戲照匯出的部件外框（`parts[].box`，兩端都含）把框裡的格**全部**收進裝甲 ⇒ 框裡不能有別的部件的格（整船框的子作品 ⇒ 整艘被收進去） |
| 2. meta | 關聯 `kind=armor`、`mount=<砲模型的路徑>`（例 `甲板-main/砲塔`）、`material`（`iron`）、要反光再加 `render=smooth`（牆至少 2 格厚；1 格粗的鐵軌別標 smooth） | 那門砲要有 `mount=turret｜pivot`；同一門砲的幾個關聯合成一塊、繞那門砲的轉軸（`g.mt.c`）跟著轉 |
| 3. 砲模型 | 模型只放砲（與砲架）；砲口在裝甲的砲門裡 | 模型外框小 ⇒ 砲班站得進圓筒裡；砲自己的血量照舊（砲種表 `hpK`） |
| 4. 量 | 框裡別的部件的格 0；轉一整圈兩個砲口都在砲門裡 | 匯入檢查「砲帶的裝甲」那一行：格數、噸數；標錯（沒 mount、找不到砲、砲不會轉、框是空的、框裡的材質不對、砲口被擋）報 ✗／⚠ |

- 遊戲裡：打到裝甲一格一格掉（實心彈、爆裂彈、鏈彈、殉爆都算），硬度與重量照材質表；平滑面被打穿會重建；剖面、拿掉甲板照船的座標切。開戰時船體 100%（裝甲不算船殼）、總重跟沒拆之前一樣。
- **砲塔是封閉的一圈**（TASK-0655；Tim 2026-10-16：「砲塔做成無法通行(這個應該要是通用規格)」「雖然會旋轉 但實際上有一圈物理阻隔通行」）：
  會轉的裝甲每一格繞轉軸掃出一圈 ⇒ 每一層掃到的半徑全部當牆（砲門跟著轉、不留縫；頂 ＝ 整個圓）。船員找路、站位、玩家第一人稱都照這一圈，走不穿；被打掉的格**不會**讓這一圈打開（砲塔還在就照樣擋）。
  ⇒ **出入只走圈裡的艙口梯**：在圈裡（離轉軸比圓筒內緣近）放一座梯子（`kind=ladders`，§9）通到下一層的艙口（莫尼特號：`梯子/turret`，住艙甲板 → 砲塔底下的艙口；史實上砲塔側面沒有門，人和火藥都從底下上來），或頂上開艙口再加梯子。⛔ **不開側門**。
  圈裡沒有梯子 ⇒ 匯入檢查 ⚠「砲塔進不去」；讀數「掃過的那一圈（走不穿）：離轉軸 a～b 格、z 範圍、圈裡的梯子」。
  ⚠ 那一圈照裝甲的格算：圓筒裡面別擺會被算進裝甲的東西（掃出來的那一圈會把圈裡的人擠出去）；砲、砲架是模型、不算。
- ⛔ 還沒做：打穿成兩半不會脫落漂走；碎屑落地、雨、船隻擦撞不看裝甲。
- 實例：莫尼特號（2026-10-16）：`-turret-armor`（圓筒，65×65×28、at 269,33,35，10,376 格、iron＋smooth）＋`-turret-roof`（鐵軌頂，65×65×2、at 269,33,63，1,903 格、iron）⇒ 12,279 格、95.8 噸；產生程式 `design/gen_armor.py`、`apply_armor.py`。鐵的硬度 Tim 2026-10-16 拉到 32（材質表，跨船共用）。
- ⚠ 2026-10-16 起砲塔改用 §4.8 的砲塔層（一座砲塔可以裝好幾門砲、可以疊）；這一節的 `kind=armor mount=<砲>` 照舊能用，適合「一門砲帶一塊會轉的裝甲」（例：砲盾跟著一門迴旋砲）。

### 4.8 砲塔層：砲塔是一層殼，上面放砲（關聯 meta `kind=turret`；TASK-0659）

Tim 2026-10-16：「讓砲塔本身只是一層殼 上面可以放置炮(跟在船體上放炮一樣) 讓炮跟著砲塔轉」「實際上可能可以在炮塔上額外加裝炮塔」「直接設定一個砲塔前方方向 然後把前方朝向瞄準方位就好 不要過於複雜的計算(特別是子砲塔跟上面的炮可能也有旋轉能力)」「砲塔內也要可以放彈藥箱」「會跟著轉的部分(砲塔吊籃) 如果砲塔是直接覆蓋一片甲板區(底下甲板不會跟著動) 就只有砲塔頂部會是一塊跟著轉的甲板」。

| 步驟 | 做法 | 為什麼（遊戲那側照什麼讀；Blockside `27_turret.js`、`24_armor.js`） |
|---|---|---|
| 1. 砲塔作品 | 一件子作品裝整座砲塔，**用船的比例**、**框收緊到砲塔**（包到砲塔頂上的東西）；殼（圓筒、頂、吊籃地板…）用關聯放進來、砲用外部模型放進來；關聯 `at` ＝ 框的原點 | 框裡的格**全部**是殼（跟 §4.7 同一套拆法）⇒ 框裡不能有船殼別的部件的格 |
| 2. 固定點 | 砲塔作品登記 `pivot`（轉軸那一格）、`front`（從轉軸往砲塔前方的一格）| 砲塔只把「前方」轉向瞄準方位（不看上面的砲朝哪）；固定點跟著關聯的鏡像、轉向換算。沒有 pivot ⇒ 外框底面中心、沒有 front ⇒ 當成船頭（匯入檢查 ⚠） |
| 3. meta | 船上那一條關聯 `kind=turret`、`arc`／`fire`／`rate`（度、度／秒，跟 §4.5 同一套；沒寫 ⇒ 一整圈、20°／秒）、`cone`（上面固定的砲對準幾度才開，預設 4） | 殼的材質、平滑寫在殼那幾條關聯自己的 meta（`material`、`render`） |
| 4. 上面的砲 | 砲的模型照 §4.2 的標法（`kind=gun`、`gun=…`）；**沒標 `mount`** ⇒ 固定在砲塔上；**標了** `mount=turret｜pivot` ⇒ 掛在砲塔底下再轉一層（照自己的砲軸對準、自己的 arc） | 砲班站位照開局的樣子排、跟著砲轉；砲甲板照最外層砲塔的底座落在哪一層 |
| 5. 彈藥箱（選） | 子樹裡一條 `kind=magazine` 的關聯＋火藥桶模型（§8） | 取用點在箱子旁、砲塔裡站得住的那一格，跟著轉；送藥手照最近的取用點拿 |
| 6. 疊（選） | 子樹裡再一條 `kind=turret`（自己的 pivot、front）| 照路徑最近的那一層分；裡面那一座照外面那一座轉過之後的角度瞄 |
| 7. 量 | 匯入檢查「砲塔層」那一行：轉軸、前方、轉的範圍、轉速、上面幾門砲、殼幾格；轉一整圈每個砲口都在砲門裡 | 砲塔底下沒有砲 ⇒ ✗（不會轉）；砲口被殼擋 ⇒ ✗ |

- **會轉的甲板**：只有**腳下是砲塔自己的格**的地方跟著轉（吊籃的地板、砲塔頂）—— 站在上面的人、走到一半的路、彈藥箱都跟著轉，那一塊的走路格照砲塔座標算（吊籃上的東西照它的位置擋）。
  砲塔**罩在甲板上**（莫尼特號：圓筒直接坐在主甲板上）⇒ 底下的甲板不轉、站在上面的人也不轉、砲塔掃過的那一圈照 §4.7 是牆。要吊籃 ⇒ 殼裡放一片地板（離圓筒內緣留一格），艙口梯落在地板中間留的洞裡（圓的洞、轉到哪都對得上）。
- **開放的砲盾**（砲班站在盾後面，例：哨兵號的速射砲，TASK-0661）：殼一定要有**平台**（砲班站的地方鋪一層砲塔自己的格）—— 沒有平台 ⇒ 盾掃過的那一圈是牆、砲班被擠到盾的寬度外，一個都擋不到。
  盾與側翼要**高過胸口**（遊戲量傷害的點 ＝ 腳底往上 9 格 ⇒ 平台上站 z ⇒ 牆至少到 z＋10）；砲尾不在那一圈裡 ⇒ 不用梯子（匯入檢查不報「砲塔進不去」）。砲管伸出盾前面那一段被打到照舊算砲（盾不替砲擋）。
  實例：哨兵號 `-shield-bow` 等五件（平台 z 35、前盾 u 8–10、側翼 |v| 12–13.5、z 到 47），產生程式 `meadow-sentinel-01m/design/apply_shields.py`。
- 停：砲塔上（含疊在上面的）的砲全滅 ⇒ 停在最後的角度。⛔ 還沒做：轉台被打壞卡住、第一人稱站在吊籃上跟著轉、吊籃上的梯子。
- 砲的血量：殼替砲擋 ⇒ 砲的 `hpK` 照一門砲算（莫尼特號 16 → 1，Tim 2026-10-16）。
- 實例：莫尼特號（2026-10-16，TASK-0660）：`meadow-monitor-01m-turret-assy`（65×65×30、at 269,33,35）：關聯 `裝甲`（圓筒）、`頂`＋模型 `砲-a`、`砲-b`（各一門 XI 吋 Dahlgren，照原本那個模型的擺法、砲-b 照 x 鏡像）＋固定點 `pivot` 32,32,0、`front` 0,32,0（開局朝船尾）；船上那一條 `砲塔` meta `kind=turret arc=-180,180 fire=-174,174 rate=16`。格子一格不動；產生程式 `meadow-monitor-01m/design/apply_turret_layer.py`。

## 5. 桅與帆桁

- 桅：每根一件子作品（fore／main／mizzen／bowsprit），軸照甲板已開的桅孔；top 的 trestletrees 要緊貼 masthead（`round(160 ± 4.56)` 會空一格 ⇒ 主桅 top 浮空，階段十三 v1.1）。
- **帆桁：每根一件子作品，模型放在它的桅子作品裡**（階段三十三）：
  - 子作品裡放**沒轉**的帆桁（沿 y），不扣跟桅重疊的格（獨立零件要完整）。
  - 固定點：`arm-P／S`（yardarm 兩端）、`earing-P／S`（帆上緣兩角）、`sling`、`jackstay-*`（每 8 格）；gaff `top*`；boom `jaws`／`end`；外加 **`pivot`**。
  - 模型：scale 1 明寫、`rotate=0,0,θ`（繞世界 z）、pivot ＝ `pivot` 那一格的格心 —— 方帆桁＝帆桁中心那一格；gaff／boom ＝ 桅在 jaws 高度的軸心（繞桅擺，pivot 不在桿上 ⇒ 子作品框要包到它）。
  - 角度：右舷那一頭往前（＋x）＝ 負角（憲法號 course −20、topsail −22、topgallant −24、royal −26；預設風 4.5,−1.5,0 正對是 18.4°）。真船受 lee shrouds 限制約 30–35°（plan.json brace 的出處欄）。
  - meta：`kind=yard, mast, yard, length_ft, diameter_in, pivot_anchor=pivot, turn_axis=z, rotate_z_deg`＋`sail`。
  - **三角帆桁（lateen；槳帆船）**：`yard=gaff`（遊戲照 gaff 往下風擺）＋ **`rig=lateen`**＋固定點 **`fore`**（帆桁前端 car，tack 綁在這裡往下拉到船頭）。遊戲照 `rig=lateen` 限制擺角：前端只能在船頭左右移 2.5 m（tack 換邊的範圍）⇒ 最多擺 asin(2.5 m ÷ pivot 到 `fore` 的水平距離)（皇家號主帆桁 10.7°、前帆桁 11.9°）。
    🩸 只標 `yard=gaff`（皇家號 2026-10-18 第一版）⇒ 照 gaff 擺到 80°，主帆桁前端甩出舷外 13 m、tack 從那裡斜拉到中央走道前端 ⇒ 看起來是一條浮在海上的纜（Tim：「發現浮空纜線」）。
- ⛔ 不要把帆桁貼進桅、也不要用格子轉角度：一格粗的截面轉了會變成只靠斜角相接的階梯（6 連通斷掉，階段二十六得把最細截面 0.5 → 0.75），拆出來要刻掉、重綁。
- ⚠ 網格轉 20° 後中段靠後那一小段會穿進桅（格子版是「不放」那 6 格）。

## 7. 帆

- 方帆：上緣（邊 0）整條釘在兩個 `earing` 之間、下兩角 free；topsail 以上的 sheet 綁到下一根帆桁同舷的 earing；course 的 sheet 往後、tack 往前綁到舷牆的 belaying pin。

- 數值：預設風 **4.5,−1.5,0**（4.7 m/s）、fullness 1.05（7.6 m/s ＋ 1.08 ⇒ 像降落傘）；帆布 #f2ead8。鼓度主要的旋鈕是**風**，fullness 只差幾格（kotoko 兩點的試驗表）。
- 帆角綁帆桁模型（`model:<桅關聯>/yard-<帆桁>/earing-P`）⇒ 帆桁一轉，帆跟著走。下角綁在甲板上的（course、三角帆的 sheet）：遊戲把 sheet 長度照「帆腳跟著這面帆的帆桁轉過之後」到甲板那一端的距離放長（Blockside 30_rig_physics.js tethYard，2026-10-18）⇒ 帆桁轉很大（拋錨、大轉彎）帆腳不會被拉回原處、整片拖到甲板（持火號前帆以前偏 7.3 m，修完 1.7 m）。
  ⇒ sheet 一定要標 `kind=sheet, sail=<帆名>`（§9.1）；帆要綁在帆桁模型上（綁最多點的那根算這面帆的帆桁）。

- 位置照圖（憲法號 1849 圖：後 x 200–271、前 x 521–574），在水線下 —— ⚠ ame 量到對戰裡砲彈碰海面就停，打不到（本來就擺在打不到的地方）。

- ⛔ **桶一定要放**（Tim 2026-10-15，維吉尼亞號）：遊戲照桶擺每層砲甲板的**取用點**（送藥手去拿火藥的地方）；彈藥庫只有關聯 meta、裡面沒有桶 ⇒ 一個取用點都沒有，砲打完砲旁藥箱那兩發就永遠停（維吉尼亞號 180 秒只開 12 發，看起來像淹水後沒火藥）。
  直接引用憲法號的 `basecamp-frigate-constitution-01m-powder-barrel`（scale 0.2、pivot 11,11,0、meta `kind=powder, powder_lb=100`），掛在**彈藥庫子作品**裡（遊戲照「彈藥庫關聯名/」認是哪一間的）。Blockside 的匯入檢查逐門砲查拿不拿得到火藥（沒有取用點、沒有送藥手、砲尾後面放不了藥箱 ⇒ ✗；取用點跟砲在走路格上不連通 ⇒ ⚠）。
- **桶可以換樣子**（Tim 2026-10-18：「彈藥箱可以有不同外觀(但實際上都能補彈)」）：彈藥庫裡模型 meta `kind=powder` 的都算火藥桶，樣子不限；遊戲的取用點（三個桶）輪流擺船上不同樣子的桶（最多三種）。

  持火號：希臘火陶罐 ×4（`store=greekfire`）、弩箭箱 ×2（`store=bolt`）（`erina-dromon-01m-store-amphora`／`-store-boltbox`，0.05 m、scale 0.5、pivot ＝ 底面正中；產生程式 `design/draft_stores.py`）⇒ 取用點擺一罐一箱一罐。
- **火藥從艙口吊上去**（彈藥庫關聯 meta `hoist=<梯子的路徑>`，例 `梯子/turret`；TASK-0632，Tim 2026-10-16：「我看火藥直接裸露在頂層甲板上 原船設計是如何搬運火藥的」）：
  那座梯子的梯頭落在哪一層砲甲板，那一層的取用點就改成這座梯子 —— 桶擺在**梯腳那一層**（室內）旁一塊 9×9 的空地、送藥手在**梯頭旁**（艙口邊）取，⛔ 不再照彈藥庫在露天甲板找空地。
  梯子路徑 ＝ 梯子關聯的路徑＋`/`＋梯名（固定點 `<梯名>.foot／.head` 的那個名字）。梯腳找不到空地或梯頭找不到站位 ⇒ 照舊找（匯入檢查看得到取用點在哪）。梯子隨時能走（Tim：「讓樓梯隨時都能通行」）。
  莫尼特號：`彈藥庫` `hoist=梯子/turret` ⇒ 取用點 1 個（砲塔裡艙口旁，桶在住艙甲板梯腳）；180 秒對維吉尼亞號照樣持續開火（原船：火藥經甲板與砲塔地板的艙口吊進砲塔，Greene〈In the Monitor Turret〉）。
  - **好幾座梯子**（逗號分開，例 `hoist=ladders-1#forecastle,ladders-1#castle`）：每一層只用梯頭落在那一層甲板（甲板 meta 的 floor）上的那一座。高起的小平台（艏樓、木塔、艉樓）沒有自己的彈藥庫 ⇒ 每座平台的梯子都寫進去。
    ⛔ 不寫 ⇒ 那幾層照彈藥庫往船頭船尾找空地：高度範圍重疊的兩層會找到同一格（持火號：艏樓、木塔的取用點疊在木塔上，三個桶把木塔內側的走道堵死 ⇒ 匯入檢查 ⚠ 走路格不連通、艏樓弩砲的送藥手從木塔直線飛過去）。
- 封閉空腔：產生程式最後局部掃一次，≤ 50 格的封閉空腔填實、新格每一塊都要連到原本的實心。

| `portlid` | 砲門蓋板模型（光榮號 `kaguya-gloire-01m-portlid`，0.1 m；TASK-0719）：一件子作品掛 N 次，掛在砲所在那一層甲板的子作品；**模型畫開著**；本身就是裝飾（不用另寫 `deco=1`） | **`lid_of`**（蓋的是哪門砲：砲的物件 id，例 `gun-7`）、`close_deg`（從模型的樣子反轉幾度關上，預設 90）、`house`（收砲時沿砲軸往船裡拉幾格，只是畫面；沒寫 ⇒ 遊戲照幾何算） | **`hinge-a`、`hinge-b`**（上緣鉸鏈，照 door 的右手定則：正轉 ＝ 往上掀、反轉 `close_deg` ＝ 關上）；P 舷 `rotate=0,0,180`，⛔ 不用 `mirror=y`。見 §9.12 |
| `galley` | 廚房的爐灶模型（光榮號 `kaguya-gloire-01m-galley`，0.05 m、scale 0.5，掛在上甲板 `-deck-spar`；TASK-0720）。⛔ 不標 `deco`（§9.9） | — | 沒有（用模型外框：遊戲在外框外找一面站得下、走得到的給廚師站，第二面給伙夫領飯）。做法見 §9.13 |

- `engine`／`boiler`／`shaft`（kotoko，Tim 2026-10-15：「遊戲中如果引擎被破壞 引擎提供的額外動力要消失（且煙會停掉）因此需要標記」）：✅ 遊戲讀了（Blockside 8c1ef46，2026-10-16；判法見 §9.6）。建議的判法同 `funnel`：固定點旁 8 格內的格子剩不到一半 ⇒ 那一件壞了；主機壞了 ⇒ 額外動力（`ships[].cfg.base`）歸零、每條煙囪停煙；某一組鍋爐壞了 ⇒ 動力照剩下的鍋爐座數打折、它 `funnel` 那條煙囪停煙。實際規則由遊戲那側定。

- `wheel`／`binnacle`／`capstan`／`boat`／`grating`／`galley` 只說「這是什麼」：站位、血量、能不能放下水、踩不踩得過去這些由遊戲決定，⛔ 不寫進 meta（餘燼號階段十七～二十、憲法號階段四十，2026-10-13 補）。

- meta 是平的 `{鍵: 字串或數字}`，`work sub=model｜link meta=` 合併進去；有 meta 的檔 schema 會升（models 2、links 3），舊 exe 讀不了會大聲擋。
- 梯子的四個點都取「腳踩的那一格」＝ 地板或踏板上面第一格空氣（讀的人取格心）：foot ＝ 下層甲板、最低一階往下梯方向站著等的那一格；lo／hi ＝ 最低／最高那一階；head ＝ 上層甲板、跨過艙口圍欄站穩的那一格（往外第一段連續 3 欄一樣高的平地）。哪兩層甲板由 foot／head 的高度判斷，不另外標。
  算點：餘燼號 `design/tools/ladder_points.py <組裝件> <甲板子作品>:<關聯名>:<梯子子作品>…`（梯名與方向從扶手繩固定點 `manrope-<梯名>-<P|S>-<top|bot>` 讀；不帶 `--apply` 只算）。
- 繩梯（橫繩組 `climb=1`，§6）跟梯子同一套：遊戲把它當一座梯子（第一人稱 E 爬、水手照 §9.3 走）。差別只在踏板是繩 ⇒ 斷不斷照橫繩（斷一半以上 ⇒ 斷了），不看格子。
- 匯出：`op=export format=parts`（外框＋meta＋固定點的 JSON）、`format=vxk include=rig,models,parts,meta`（給遊戲；out 要絕對路徑）。改完任何部件都重匯一次，**格數與 checksum 會變**，要跟遊戲那側說。

### 9.1 帆、繩、旗的 meta（遊戲照 meta 判斷；TASK-0539）

Tim 2026-10-13：「之後依 meta 判斷吧（然後需要定義好 meta）」。帆與繩也能帶 meta（`work sub=meta`，見 `Sculpture.md` §9.4.9「帆與繩的 meta」）——

| `kind` | `sail`／`flag` | 旗：不收、不算推力 |
| `mast` | `fore`／`main`／`mizzen`／`bowsprit` | 掛在哪根桅（跟帆桁 meta 的 `mast` 同一套；三角帆掛艏斜桅 ⇒ `bowsprit`） |

| `set`（帆，可選） | `1`／`2`／`3` | 例外：最少在哪一段帆裝打開（1 收帆、2 戰鬥帆、3 滿帆）—— 跟種類的預設不同才寫（憲法號 fore-topmast-staysail `2`、flying-jib `3`；只有兩面帆的船要分得出段：持火號前帆 `3`、中帆 `1` ⇒ 收帆、戰鬥帆只張中帆，Tim 2026-10-18「沒有單帆狀態」） |

### 9.2 空艙房（遊戲配置功能艙；TASK-0568）

遊戲（《憲法號對轟》）把空艙房當容器：玩家在船隻配置頁選房間類型（醫療艙…），在 0.5 m 一格的俯視格子上擺物品（病床、手術台、藥箱），或一鍵自動擺滿。**空艙房 ＝ 一個長方體**，標在艙房那件子作品裡：

- 固定點 `<房名>.min`、`<房名>.max`：兩個角的那一格（含兩端）。**只框空氣**；地板 ＝ 甲板面上第一層空氣（跟梯子 foot 同一個量法），頂 ＝ 上一層甲板底下那一格。房名照舊自己取（例 `1`、`2`…）。
- 可選 `<房名>.door`：門口站人的那一格（沒標 ⇒ 遊戲自己從四面牆找通出去的格）。
- 那條關聯 meta `kind=rooms`（meta 誰都能標）。**鏡像的關聯固定點會自己翻過去** ⇒ 一舷標一次、另一舷的那條關聯也標 `kind=rooms` 就好。
- 遊戲裡的名字 ＝ 關聯路徑／房名（例 `甲板-berth/艙房/3`、`甲板-berth/艙房-鏡像/3`）。艙房照關聯路徑屬於那一層甲板（§9.3）。

遊戲怎麼用這個框（標之前先想好）：

- 框裡切成 0.5 m（5 格）一格，零頭平分在兩邊。一格要整格腳下實心、頭上 1.4 m 內都是空氣才能擺 ⇒ 框貼著牆、地板要平。
- 門 ＝ 四面牆上往外連續 0.8 m 站得住的那幾格。門口那一格（加上門的兩旁各一格）留給走道、不能擺；每件物品都要有一邊從門口走得到。
- 病床 1.9 × 0.8 m 佔 4 × 2 格 ⇒ 要擺得下一張床，房間最少約 2.0 × 1.5 m（門開在短邊 ⇒ 長邊要 2.5 m）。更小的照樣標，配置頁會寫「放不下」。
- 那一層甲板沒有梯子通到 ⇒ 配置頁標「走不到」（傷員送不過去）。

候選與檢查（遊戲那側的工具，讀 `Blockside/VoxelKit/_cache` 的 .vxk）：

```bash
python -I Blockside/src/rooms.py scan  --id <船的代號>   # 候選：每個「艙房」部件裡被牆隔開的每一間 ⇒ 最大的全空氣長方體；印組裝件座標與子作品自己的座標（sub=anchor 直接用）
python -I Blockside/src/rooms.py check --id <船的代號>   # 標好的：尺寸、裡面幾格不是空氣、跟別間重疊幾格、門；不合格的打 ✗
```

- ⚠ 候選照「關聯路徑結尾是 艙房／艙房-鏡像」找；艙房叫別的名字 ⇒ 自己量。scan 的座標是匯出當下的作品，改過船要重匯再掃。
- 憲法號、餘燼號（2026-10-14 量）：每舷 orlop 7、berth 8、砲甲板 2（餘燼號 orlop 多 1）；夜隼號沒有隔出來的艙房。拿候選試排醫療艙：憲法號 34 間有 20 間放得下病床、餘燼號 36 間有 22 間。
- 標完到遊戲裡看：`admin.py metasync --id <船>`（或重新匯入）、重建 ⇒ 船隻配置頁「甲板與艙房」一間一列；`?rooms=1` 畫出每一間的外框與名字。

### 9.3 甲板與通道（遊戲照 meta 判定甲板；TASK-0572）

遊戲照甲板分層（砲甲板、預備水手走得到的層、停格拿掉甲板、艙房屬於哪一層），⛔ 不自己量層高。結構：甲板 → 房間 → 功能物品（床、砲）；甲板本身也是一個大房間。

**甲板**：組裝件裡那條甲板關聯（在 0,0,0）的 meta（meta 誰都能標）

| 鍵 | 值 | 用途 |
|---|---|---|
| `kind` | `deck` | — |
| `deck` | 代號（`orlop`、`berth`、`gun`、`lower`、`upper`、`spar`、`poop`、`main`、`quarter`…） | — |
| `level` | 由下往上，0 起 | 順序 |
| `name` | 顯示名（底艙甲板、住艙甲板、砲甲板…） | 停格、廣播、配置頁 |
| `floor` | 舷弧 `"x:z,x:z,…"`：z ＝ 地板上第一層空氣；點之間線性內插，範圍外 ＝ 這一層在那裡沒有甲板 | 走路格、切面 |
| `thick` | 地板＋底下的樑幾格 | 停格拿掉甲板切多深 |
| `walk`（可選） | 同 `floor` 的寫法：人走的那一層面不是地板的地方 ⇒ 走路格照它，範圍外照 `floor`；判層、停格、艙房照舊照 `floor` | 走路格 |

- 量：每一層甲板子作品單獨匯出 .vxk，`python -I Blockside/src/decks.py --vxk 甲板-berth=<…vxk> …  --tsv <out.tsv>`，再 `work sub=meta file=<out.tsv>` 標上去；遊戲那側 `admin.py metasync --id <船>` 同步（只換 meta 與固定點，格子不動）。
- 房間、梯子、砲照**關聯路徑**屬於那一層（`甲板-berth/艙房`、`甲板-berth/梯子`）；路徑看不出來的照高度落在哪一層。
- **`walk`：槳帆船**（皇家號 2026-10-18）：甲板上排滿划手座，人走的是比地板高 0.9 m 的中央走道（coursier）—— 走路格只看 `floor` 上下 −2～+3 格 ⇒ 甲板被座切成三十幾塊、送藥手的路全斷（匯入檢查「火藥」0／19 門走得到）。
  `walk` 照中央走道頂（＋1）逐格量、兩頭連著台階（每階 ≤ 3 格）⇒ 走路格從艙口梯頭一路通到船頭砲台底下（「火藥」0／19 → 5／19；剩下的是舷外槳架上的迴旋砲，那裡本來就不是走道）。⛔ 不要直接把 `floor` 改成走道高：判層照 `floor`（地板上 −3～+20 格），甲板面上的東西會被判到下一層去。量法範例：`design/draft_cabins.py`（照遊戲 navZ／navStep 算連通，改之前 ✗、改之後 ✓ 當反向對照）。

**通道**：梯子（§9 `kind=ladders`，foot／lo／hi／head）。兩頭各落在哪一層照那一欄的 `floor` 判斷（x 也看：兩層高度重疊、前後不重疊也分得開 —— 風暴角號後甲板與艏樓）。
- **繩梯也是通道**（TASK-0678，Tim 2026-10-17「跨甲板也可以靠繩梯」）：橫繩組 `climb=1`（§6）的 foot／head 兩頭都落在甲板上（照 `floor` 判，同梯子）⇒ 預備水手也走它；一頭不在任何一層甲板上（例：桅頂平台，離甲板地板 20 格以上）⇒ 只有第一人稱爬得上去，水手照舊走梯子、⛔ 不會因為它多出一層。直接指定兩層：繩梯沒有關聯 meta 可寫 `.decks` ⇒ 目前只能照 `floor` 自動判。⚠ 跨甲板的繩梯（2026-10-17）只有程式路徑、還沒有一艘船實際用過。
- 要直接指定：同一條梯子關聯的 meta 加 `<梯名>.decks`，值是兩層的 `deck` 代號、`name` 或 `level`，逗號分隔（例 `{"bak-P.decks":"upper,forecastle"}`）⇒ 遊戲照它接，不看其他判定；level 低的那層接 foot。寫錯（找不到那層）⇒ 遊戲主控台警告、照 `floor` 自動判。
- 兩頭各自離那一層的走路格太遠（自動判 1 m、直接指定 2 m 內接不上）⇒ 那座梯子不用。遊戲裡 lo、hi 底下的踏板被打掉、或兩頭的甲板被打穿 ⇒ 那條通道斷（遊戲設定「尋路更新」開著時）。
- 沒有梯子通到的甲板 ⇒ 預備水手走不到（憲法號、餘燼號的 orlop 現在沒有梯子）。
- **第一人稱：每個掉得進去的地方都要爬得出來**（拿破崙號 2026-10-16，Tim：「掉到引擎倉沒有樓梯上不去」）。`81_fps.js` 往下踩得下 0.8 m、往上只跨得上 0.6 m ⇒ 船底內側的弧面是一段**只能往下的台階**；沒鋪甲板的大艙（機艙、貨艙）走得進去、走不回來。量法：照遊戲的走法（四鄰那一柱、上 ≤ 6／下 ≤ 8 之內**離腳最近**的高度，同 `fpStand`）建一張有向圖，「從甲板走得到的」減「走得回甲板的」要是 0 —— ⛔ 只量「走得到」會以為沒問題；⛔ 窗裡任何一個高度都算 ⇒ 會從斜殼外面掉進殼底下（遊戲不會）。範例：拿破崙號 `design/draft_engine_access.py`（`reach`）；整艘船量：`works/basecamp-ember-01m/design/tools/walkback.py`。
  - **讀數要寫量的框**（basecamp 2026-10-17，TASK-0519 留言 #4）：同一艘拿破崙號拿掉機艙梯子，只框機艙（x 300–680、z ≤ 92）⇒ 回不來；整艘船量 ⇒ 回得來（沿船殼內壁一格一格往船尾爬到 orlop）。兩份都對，是框不同 ⇒ 報「回不來 N 格」時一併寫框與起點。而「走得回」＝ 規則允許，⛔ 不等於玩家找得到那條路：船殼內壁那種陡台階只有讀數會去爬 —— 拿不準就同時報「只算 0.3 m 台階」那一欄。
  - **反向對照拿掉梯子要連格子一起藏**：只拿掉梯子的點（meta）、格子留著 ⇒ 讀數一格都不變（踏板 3 格一階，本身走得上去）。
- **機艙也可以是一層甲板**：鋪一層地板（鐵板，留排水孔 ⇒ 板底下不封成空腔）、甲板 meta `level` 給 −1（`35_decks.js` 照 level 排序，排在最下面那層底下）⇒ 船員走得下去（梯子加 `<梯名>.decks`）。範例：拿破崙號 `甲板-engine`（`deck=engine, level=-1, name=機艙`）。

### 9.5 材質（遊戲照材質算防禦與重量；TASK-0616）

- **全船預設材質**在遊戲那側設（`config/game.json` 的 `ships[].material`，後台「船隻」那一格；沒寫 ⇒ 材質表的預設，現在是橡木 `oak`）⇒ 造船這側**沒寫就是木頭**，什麼都不用做。
- **子作品要換材質**（例：木船水線上包一層鐵甲、水線下包銅皮）⇒ 那條**關聯**的 meta 加 `material=<材質 ID>`（`work sub=meta part=link name=<關聯名> meta={"material":"iron"}`；meta 不限作者）。
  - 自己沒寫 ⇒ 照上一層（關聯底下巢狀的關聯照它的父關聯；都沒寫 ⇒ 全船預設）；自己寫了 ⇒ 蓋過上一層。
  - 重疊的格照「已有的格贏」：材質跟著先放進去的那一格（主作品自己的格 ＞ 前面的關聯 ＞ 後面的關聯，同 `link_overlap`）。⇒ 裝甲最好是獨立一件子作品、不跟船殼重疊。
  - 只看**關聯**；外部模型（砲、帆桁…）不吃 material（它們整塊打飛，沒有逐格的防禦）。
- **材質 ID 一律英文小寫**（`oak`、`pine`、`teak`、`iron`、`copper_sheath`、`boiler`、`glass`…；木頭可以分），參數（防禦、比重、易燃）在遊戲那側的材質表（`config/game.json` 的 `materials`，後台可以加、可以改），跨船共用 ⇒ 造船這側只寫 ID。寫了材質表沒有的 ID ⇒ 遊戲照全船預設、匯入檢查報 ⚠。
- **平滑渲染**（鐵甲艦光滑的裝甲、煙囪、駕駛塔）：關聯的 meta 加 `render=smooth`（巢狀、重疊的規則跟 material 一樣；子關聯寫 `render=voxel` 蓋回方塊）。遊戲把這幾格畫成平滑的表面（surface nets），跟旁邊的方塊格接在一起不露縫，被打掉照樣重算；打中、進水、重量照舊看格子。
  - 平滑面的厚度至少 2 格（1 格厚的薄板兩面會被平均到一起）；跟一般格相鄰的那一圈會釘在格角上（看起來比較硬）⇒ 想要整片平滑，就把那一整片都標進去。
  - 匯出時檔頭多一個 `render`（同 materials 的格式）；沒有關聯寫 ⇒ 沒有這個鍵。範例：維吉尼亞號（`ame-virginia-01m`）的砲廓鐵甲、駕駛塔、煙囪、撞角。
  - **金屬會反光**（TASK-0627）：材質表裡有 `metal`／`rough` 的材質（現在 iron、copper_sheath）在**平滑渲染**的面上有天空反射與太陽高光；方塊格的面還不反光 ⇒ 要看起來是金屬的鐵甲、煙囪，關聯同時標 `material=iron` 與 `render=smooth`。
  - **金屬件自動平滑**（Tim 2026-10-17：「把鍋爐 螺旋槳 以及其他金屬部件都改成光滑金屬質感」）：遊戲的材質表標了 `smooth` 的材質（現在 `iron`、`boiler`；包銅皮不標）⇒ 關聯只寫 `material=iron`（或 `boiler`）、沒寫 render 也畫成平滑＋反光；螺旋槳（會轉的體素件）整份平滑。⇒ 要留方塊的鐵件（1 格粗的鐵軌、格柵、薄的欄杆）**明寫 `render=voxel`**。⚠ 只有遊戲自動：雕刻觀測頁、CLI view 照舊只看 `render=smooth` ⇒ 交船前想在觀測頁看到一樣的樣子，照舊標 `render=smooth`。
  - **雕刻觀測頁與 CLI view 也照畫**（TASK-0645）：同一組 meta、同一套平滑算法；反光的金屬度、粗糙度照**雕刻自己的材質表** `Sculpture/materials.json`（跟遊戲那份各管各的；新的材質 ID 兩邊都要加）⇒ 交船前在觀測頁就看得到平滑與反光。細節見 `Sculpture.md` §5.5。
  - **金屬部件一覽：一律標成光滑金屬**（Tim 2026-10-18：「金屬部件參考拿破崙號 設定為光滑金屬質感」；照拿破崙號 2026-10-17、光榮號 2026-10-18）—— 每一件是**獨立的關聯**、meta 照下表寫齊 `material` ＋ `render=smooth`（遊戲那側的材質表會自動平滑，但觀測頁只看 `render`，⇒ 兩個都寫，交船前在觀測頁看得到的就是遊戲裡的樣子）：

    | 鐵甲帶、砲廓、駕駛塔／指揮塔、煙囪、撞角 | `material=iron`、`render=smooth` | 真的是鐵（防禦、重量照 iron）；牆至少 2 格厚 |

    | 鍋爐（含頂上的煙道殼） | `material=boiler`、`render=smooth` | ⛔ 不標 iron：實心格 ＝ 鐵殼＋滿水（boiler 密度 0.9；iron 會多好幾千噸）；外觀照金屬反光 |

    - ⚠ 外部模型（砲、錨、齒輪、曲柄、陳設）**不吃 material**、也不照關聯的 render ⇒ 金屬感照模型自己的顏色；要逐格的鐵就得做成關聯。
    - 範例：拿破崙號（主機、軸 iron＋smooth；兩組鍋爐 boiler＋smooth；兩根煙囪 iron＋smooth）、光榮號（鐵甲帶、指揮塔、煙囪、主機、軸 iron＋smooth；鍋爐 boiler＋smooth）。

    - **重量**：比重 2.5 ⇒ 一格 2.5 kg（橡木 0.7）；窗只有幾百到兩千格，整艘差不到 5 噸。

### 9.6 蒸汽動力怎麼設：主機、鍋爐、煙囪、軸、螺旋槳（鐵甲艦、蒸汽艦）

§9 的 kind 表說「標什麼」，這一節說「怎麼做」。範例：維吉尼亞號（ame，煙囪＋機艙）、拿破崙號（kotoko，主機＋兩組鍋爐＋兩根煙囪＋軸）、光榮號（kaguya，螺旋槳模型；2026-10-18 臥式回行連桿主機直接驅動 ⇒ 沒有齒輪、曲柄做成會轉的模型 `spin_k 6`；八座鍋爐一組、通唯一那根煙囪；產生程式 `kaguya-gloire-01m/design/draft_engine.py`）。

**作品怎麼拆**：每一樣是一件子作品（`tags=sub`），**用整船的框**、組裝件關聯 `at 0,0,0`；meta 標在**關聯**上、固定點登記在**子作品**裡（組裝件座標 ＝ 子作品座標，不用換算）。一舷做、另一舷 `mirror=y` 的部件，鏡像那條關聯的固定點會自己翻過去。

| 部件 | 怎麼雕 | 關聯 meta | 固定點 | 遊戲現在讀不讀（2026-10-15） |
|---|---|---|---|---|
| 煙囪 | 空心管（牆 ≥ 2 格才能 `render=smooth`）；**甲板以下往下接到煙箱的那段直煙道也放在煙囪部件裡**（同一根、同材質 ⇒ 艙裡看得到的那段一樣是鐵、反光；⛔ 放在鍋爐部件 ⇒ 看起來分兩段、艙裡那段沒有金屬質感 —— Tim 2026-10-17，維吉尼亞號） | `kind=funnel`、`material=iron`（要反光再加 `render=smooth`） | **`smoke`** ＝ 煙囪口頂那一層的中心（空心的正中間也可以） | ✅ 讀（`78_funnel.js`）：從 `smoke` 冒煙；排煙點水平 ±12 格、往下 6 格內的格子剩不到開局的一半 ⇒ 不冒。⚠ 那個範圍裡開局就 0 格（煙囪半徑 > 12 格、或 `smoke` 放在口的上方太高）⇒ **永遠不冒** |

| 主機 | 汽缸、曲柄或槓桿、底座 | `kind=engine`、`engine`（`direct`／`geared`…）、`cylinders`、`ihp`／`nhp`、`kn`、`kn_max`、`maker`（⚠ 沒查到的不寫）；可選 `material=iron` | **`core`**（主機中心）、可選 `cyl-1／cyl-2`、`gear`；站位 `tend-1…n`（機匠站的那一格，見表下） | ✅ 讀：core 旁 ±8 格剩不到一半 ⇒ 主機壞了、它那一份額外動力沒了；全壞 ⇒ 每根煙囪停煙。幾具主機照 `ihp` ＞ `nhp` ＞ 1 分份量；可選 meta `propeller` ＝ 螺旋槳模型的名字（指定推哪一個） |
| 軸 | 從主機穿過 deadwood 到螺旋槳 | `kind=shaft`、可選 `material=iron` | `aft`、`fwd` | ✅ 讀：主機接 fwd 離 core 最近的軸；軸接 aft 離螺旋槳 hub（或 shaft-fwd）24 格內最近的那個；aft／fwd 旁 ±8 格任一邊剩不到一半 ⇒ 軸斷、接在上面的螺旋槳收不到。沒有螺旋槳模型 ⇒ 推力放在 aft 端 |
| 螺旋槳 | **外部模型**（不是關聯）：子作品用整船的框、模型 `at ＝ pivot ＝` 轉軸中心、scale 1 | 模型 meta `kind=propeller`、`axis_x／axis_y／axis_z`、`blades`、`diameter_m` | `hub`、`shaft-fwd` | ✅ 轉：轉速 ＝ `rpm_max` × √(它那一份推力 ÷ 完好時全速的推力)，倒車反轉；血量跟舵一樣；掛在 shaft-fwd 旁 8 格內的船殼上（沒有 shaft-fwd ⇒ 往正下方找，⚠ 外框底下 12 格內要有格子）；被打飛 ⇒ 綁在上面的動力出不來 |
| 蒸汽管 | 從鍋爐（煙道旁）接到主機的管；穿過隔艙壁那一段可以留在船殼裡 | `kind=steampipe`、可選 `material=iron` | `from`（鍋爐那頭）、`to`（主機那頭） | ✅ 讀（TASK-0653）：接 `from` 離它最近的那一組鍋爐；那一組的蒸汽 × 蒸汽管傳得到幾成。沒有蒸汽管的組照舊直接供汽 |

- **動力件照自己的格子算**（TASK-0653，Blockside 2026-10-16；Tim：「不是直接根據該子模組當前剩下多少voxel計算嗎」「槳軸是否可以是類似mc紅石電路概念的東西 傳遞動力」「被打細了傳得比較少」）：主機、鍋爐、軸、蒸汽管的關聯，`admin.py` 匯出時把來源作品的格子寫進檔頭（`parts[].cellRuns`）⇒ 遊戲每 1 秒照實數，取代上表「±8 格」那個退路（沒有格子清單的船照舊）：
  - 體素件（主機、鍋爐）：還剩幾成 ＝ 還在的格 ÷ 開局的格 ⇒ 輸出照曲線（主機剩 40% 以下 0、100% 全力；鍋爐 50% 以下 0、80% 以上全力；中間直線）。鍋爐每一座中心那一格泡在艙內的水裡（淹到一半）⇒ 那一座熄火。
  - 傳動件（軸 `fwd`→`aft`、蒸汽管 `from`→`to`）：像電線 —— 兩端之間互不共用格子的路最多幾條（26 鄰，最細的那一截）× 每格傳 15% ⇒ 大約 **7 格粗才傳得滿**；打斷 ⇒ 0、打細 ⇒ 打折。開局就傳不滿 ⇒ 照開局當滿載（匯入檢查 ⚠：雕粗一點）；開局就不通 ⇒ 判不了、當作一直通（匯入檢查 ⚠）。
  - **穿過船殼那一段不用拆出來**：軸穿過尾柱、隔艙壁的那幾格算船殼的也可以 —— 遊戲沿兩端固定點的連線、照軸自己的粗細借船殼的格接起來（三艘鐵甲艦都是這樣接通的；借來的格被打掉 ＝ 軸管爛了，一樣傳不過去）⇒ **兩端固定點要放在軸的中心線上（格心）**。
  - 曲線、泡水熄火、每格傳幾成都在遊戲的道具設定頁「（動力件）」那幾項調（設定檔 `drvparts`）；⛔ 不寫進 meta。
  - 匯入檢查（`admin.py shipcheck`）列每一件的格數、借了幾格、開局幾條路、傳不傳得滿。⚠ 只認關聯 `turn` 0、`mirror` 空或 `y`（其他照舊判法）。
- **螺旋槳是會轉的體素件**（TASK-0653 第二段，Blockside 2026-10-16）：`kind=propeller` 的外部模型，`admin.py` 匯出時把來源作品的格子帶進檔頭（`rig.models[].vox`）⇒ 遊戲裡跟著軸轉、被打到一格一格掉、推力照還剩幾成套曲線（預設剩 20% 以下 0、90% 以上全力；道具設定頁「螺旋槳（動力件）」）。硬度照模型 meta `material`（沒寫 ⇒ iron），當**鑄件**：不凹不彈、照硬度打洞。掛法照舊（`shaft-fwd` 旁那一格被打斷 ⇒ 整個掉）。
  - ⛔ 模型要**平移放**（at ＝ pivot、不旋轉、不縮放、不鏡像；三艘鐵甲艦都是）—— 不然匯不出格子、照舊當模型扣血（匯入檢查 ⚠）。
  - 照參數轉的機件（`spin`；齒輪、飛輪）沒有 `bail` 時，遊戲改掛在 `spin-a` 旁那一格（不用再借燈的 `bail`）。

- **站位：模型只標「人站哪一格」，參數都在遊戲端**（Tim 2026-10-16：「動力部件可以設定需要船員工作(鍋爐) 沒有會影響輸出」「動力部件相關參數其實我希望都在遊戲端設定(後台預設 遊戲內可調參數) 模型只提供meta標記」）。固定點登記在那件部件的子作品裡：鍋爐 `stoke-1…n`（每座爐門前、燒火通道裡、地板上第一格空氣）、主機 `tend-1…n`（汽缸旁）。⛔ 要幾個人、人不夠怎麼扣出力不寫進 meta。站位要站得住（腳下實心、頭上 1.2 m 空）、走得到（那一層有甲板 meta 與梯子，見 §9.3 機艙那一條）；燒火通道要夠寬（史料 2.4–3 m，推）。範例：拿破崙號（兩組各 4 座、通道 2.1／2.3 m；主機 2 個）。⚠ 遊戲還沒讀（2026-10-16）。
- **會轉的機件**（齒輪、飛輪）：照螺旋槳拆成外部模型（整船的框、at ＝ pivot ＝ 轉軸格心），模型 meta `kind=gear` ＋ §9.8 的 `spin=rpm, spin_mode=rate, spin_k`（螺旋槳軸上的 ＝ 6；跟它咬合的 ＝ −6 × 小齒輪半徑 ÷ 大齒輪半徑）、固定點 `spin-a`→`spin-b`；**還要 `bail`**（掛點：轉軸上旁邊 8 格內有船的格）—— 沒有 ⇒ 外框底下 12 格內沒有格就被當成吊著的小艇、spin 不收（匯入檢查 ⚠）。範例：拿破崙號 `大齒輪`／`小齒輪`（`design/tools/split_gears.py`）。往復的連桿 spin 做不到。
- **煙多煙少、船會不會自己走，看的不是這些部件**：遊戲設定檔的 `ships[].cfg.base`（額外動力，節；遊戲那側填，例 維吉尼亞號 5.5、拿破崙號 12）。`cfg.base > 0` 而且在全速前進／倒車 ⇒ 濃煙；停車或沒有額外動力 ⇒ 淡煙。沒有帆又沒有 `cfg.base` ⇒ 船不會動（匯入檢查 ⚠）⇒ 交船時在 notes 寫下史料的航速、主機馬力，給遊戲那側填。
- 兩根煙囪靠在一起（例：並排的兩根方煙囪）：各自 ±12 格的範圍會數到對方 ⇒ 打斷一根，另一根的格子還算在裡面，可能照樣冒 —— 要分得開就讓兩根的排煙點隔 25 格以上，或接受（照實寫）。
- 煙囪也可以做成外部模型（模型 meta `kind=funnel`）：被打到歸零整根飛走 ⇒ 不冒；但外部模型不吃 material、不算逐格。
- 主機／鍋爐／軸的建議判法（給遊戲那側；kotoko，Tim 2026-10-15）：固定點旁 8 格內的格子剩不到一半 ⇒ 那一件壞了；主機壞 ⇒ 額外動力歸零、每根煙囪停煙；某組鍋爐壞 ⇒ 動力照剩下的座數打折、它 `funnel` 那根停煙。⇒ `core`、`boiler-n` 旁邊 8 格內要有格子（判法比的是「開局有幾格、現在剩幾格」；空心箱子的正中間 8 格內沒有格子 ⇒ 量不出壞了沒有）。

### 9.7 門與艙蓋（模型 meta `kind=door`；TASK-0638）

Tim 2026-10-16：「艙門機制 有人經過才打開 且打開只是演出效果」「門要另外建子模型 且可被破壞 …… 可以讓人員進出(直接視為通道) 但是會阻擋水流入」「門可以有上下開 & 左右開 純粹演出」。範例：莫尼特號 `meadow-monitor-01m-hatch`（主甲板的前艙口、機艙艙口）。

- **一扇門一件子作品**，當外部模型掛在出入口所在那一層甲板的子作品裡（`work sub=model … meta={"kind":"door","open":"up"}`）。門比開口每邊大一格、平貼在開口上面（艙蓋：外框底面 ＝ 甲板頂的上一格）；遊戲把**門外框正下方、甲板那一層原本就空的格**當成這扇門的開口。
- 門子作品裡登記 **`hinge-a`、`hinge-b`**：鉸鏈軸上兩點。從 hinge-a 看向 hinge-b，照右手定則正轉 ＝ 開門的方向（艙蓋鉸鏈沿 +x、門板往 +y 伸 ⇒ 往上掀）；反了把兩點對調。鉸鏈水平 ＝ 上下開，垂直 ＝ 左右開；`open=up｜side` 只是說明，跟鉸鏈對不上匯入檢查報 ⚠。雙扇門 ＝ 兩個門模型、各自的鉸鏈。可選 `open_deg`（開到幾度，預設 100）。
- 遊戲怎麼用（Blockside `25_doors.js`）：
  - **通道**：門不擋人，關著也照走（走路格、梯子不看它）⇒ 出入口本來的梯子照樣要標（§9 `ladders`）。
  - **演出**：有人經過（走路、爬梯子）離門 1.5 m 內才開，走了 1 秒關；畫質設定「門的開關演出」關掉 ⇒ 一直關著。只改畫面。
  - **擋水**：門在 ⇒ 那個開口不進水；門被打掉（血量砲的一半）或鉸鏈旁的甲板被打掉（門掉了）⇒ 開口變成進水口，甲板上的水面（照浪）淹過開口就灌進去。⚠ 沒有門的開口遊戲不當成進水口（甲板上浪打過來沒做）⇒ 低乾舷的船（莫尼特號這一類）露天的出入口都該有門。
- 砲門 ⇒ §9.12（`kind=portlid`：鉸鏈照這一套，可是不當門 —— 不登記開口、不擋水、本身是裝飾；Tim：「炮門也可以套用類似概念」）。

### 9.8 照參數轉的子物件：舵、舵輪（模型 meta `spin`；TASK-0640）

Tim 2026-10-16：「跟隨船隻轉彎方向去轉舵輪&舵(參考螺旋槳跟船速關聯)」「綁定某項參數&某個子物件的旋轉關聯(meta設定)」「舵面本身應該要有上限 舵輪可以沒有(可以轉超過一圈)」。
通用的綁法：模型 meta 寫 `spin` 就綁，**遊戲不看種類名**；沒寫 ⇒ 不轉（跟以前一樣）。

| meta | 意思 |
|---|---|
| `spin` | 來源參數：`rudder`（舵角 −1..1，左舵 ＝ 往左舷轉為正）｜`speed`（航速，節；倒退為負）｜`rpm`（螺旋槳轉速：自己是動力的輸出物件 ⇒ 自己的，否則這艘第一個螺旋槳的） |
| `spin_mode` | `angle`（預設）：角度 ＝ `spin_k` × 參數｜`rate`：每秒轉 `spin_k` × 參數 度（一直轉；rpm × 6 ＝ 每秒幾度） |
| `spin_k` | 倍率（度／參數單位；預設 1）；負的 ＝ 反著轉 |
| `spin_min`／`spin_max` | 上下限（度）；**沒寫 ＝ 那一頭無上限**（舵輪可以轉超過一圈） |
| `spin_lag` | 跟上的時間常數（秒；預設 0.3；0 ＝ 立刻）；angle 模式才用 |

- **轉軸**（照順序找第一個有的）：模型的固定點 `spin-a` → `spin-b`（中心 ＝ spin-a）｜meta `spin_pivot_x／y／z` ＋ `spin_axis_x／y／z`（組裝件座標，跟舵的 hinge_* 同一種寫法）｜舵的 meta `hinge_*` ＋ `axis_*`（§9 rudder 那一列，舵不用另外寫軸）｜固定點 `hub-aft` → `hub-fore`｜固定點 `hub` ＋ meta `axis_*`（螺旋槳）。
- **方向**：繞轉軸照右手定則（格座標 x 往船頭、y 往右舷、z 往上）。舵的軸朝上 ⇒ 正轉 ＝ 後緣擺向左舷 ＝ 左舵 ⇒ `spin_k` 寫正的；舵輪的軸朝船頭 ⇒ 正轉 ＝ 輪頂往左舷（「往要去的方向轉輪」）。
- **只是畫面**：轉了不影響碰撞、不改戰局；被打飛時擺回 0°。⛔ 掛著擺的小艇、門不收（它們自己在轉）。螺旋槳寫了 `spin` ⇒ 照這一套；沒寫 ⇒ 照 §9.6（遊戲照推力算轉速）。
- 匯入檢查：來源不認得、找不到轉軸、上下限顛倒、寫在小艇或門上 ⇒ ⚠；讀數那一行列出每個會轉的模型。
- ⚠ 還沒做：舵柄上的繩不跟著舵轉（滿舵時繩頭會離開舵柄）。

#### 9.8.1 每艘船都要配：舵與舵輪（Tim 2026-10-16：「要配置舵與舵輪」）

遊戲只轉**模型**（外部模型，`work sub=model`），⛔ 不轉關聯、更不轉船殼裡的格子。

| 部件 | 必要條件 | spin meta（照抄） |
|---|---|---|
| 舵 | 模型 `kind=rudder`＋`hinge_x／y／z`、`axis_x／y／z`（舵繞的那條線，組裝件座標）、`max_deg`、`turn_axis=hinge`；舵子作品登記固定點 `stock-top`（舵頭） | `{"spin":"rudder","spin_k":<max_deg>,"spin_min":-<max_deg>,"spin_max":<max_deg>,"spin_lag":0.3}` —— 軸用舵本來的 hinge／axis，不用另外寫 |
| 舵輪 | 模型 `kind=wheel`＋固定點 `hub-aft`、`hub-fore`（輪軸的兩端；共用的舵輪元件已經有） | `{"spin":"rudder","spin_k":540,"spin_lag":0.6}` —— 軸自動取 hub-aft → hub-fore；⚠ 540° ＝ 滿舵一舷一圈半，是挑的，不是史料 |

- 寫法（meta 不限作者 —— 遊戲用的資訊，誰都能補；Tim 2026-10-16「直接修改吧 不影響作品本身」）：
  `senate cmd sculpture --arg op=work --arg sub=meta --arg part=model --arg work=<模型所在的作品> --arg name=<模型名> --arg 'meta={…}'`。
  模型在甲板子作品裡（部件清單路徑「甲板-spar/舵輪」）⇒ `work` 填那條關聯的作品、`name` 填斜線後面那一段。
- 舵輪的軸也可以自己給（夜隼號、風暴角號的寫法）：`spin_pivot_x／y／z`（axle 固定點）＋`spin_axis_x／y／z`（朝船頭 1,0,0）。
- 讀回：`senate cmd sculpture --arg op=export --arg format=parts --arg work=<組裝件>`，每個 `kind=rudder`／`kind=wheel` 的模型 meta 裡都要有 `spin`。

**舵還是關聯（獨立子作品）或船殼裡的格子 ⇒ 改成模型**（⚠ 改模型、關聯、格子**只有作者能做**；改完舵會跟其他船一樣能被打飛 —— 打飛後只剩調帆轉向）：

1. 舵在船殼格子裡 ⇒ 先把舵的格（舵葉、舵柱、舵柄）切成獨立子作品：子作品跟組裝件同框、at 0,0,0 最省事（`carvevox` 從船殼拿掉、`stampvox` 落進新子作品，兩份清單同一份格）。
2. 量鉸鏈：每一層 z 取舵葉朝船頭最遠那一格（前緣）⇒ 擬合直線 x ＝ a ＋ b·z（丟掉離線超過 1.5 格的層：頂上往船頭伸出去的舵柄）⇒ `axis ＝ normalize(b, 0, 1)`，`hinge ＝`（前緣格角的外包絡在最低那層的 x、舵的中線 y、最低那層 z）。
   這把尺拿四艘作者自己標的舵對過：潮墓號、收穫號、拿破崙號的鉸鏈都在作者值 ±0.4 格內、軸向差 ≤ 0.0007（夜隼號差 3 格 —— 它的 hinge 是舵柱中心線，不是前緣；兩種都轉得起來）。
3. 舵子作品登記 `stock-top`（最高那層、舵頭那一格）：`work sub=anchor --arg work=<舵子作品> --arg name=stock-top --arg at=x,y,z`。
4. 組裝件拿掉舵的關聯、改掛成模型（同一件子作品、原位）：
   `work sub=unlink --arg name=舵`；
   `work sub=model --arg name=舵 --arg source_work=<舵子作品> --arg pivot=<P> --arg at=<P＋關聯的 at> --arg scale=1 --arg 'meta={"kind":"rudder","hinge_x":…,"hinge_y":…,"hinge_z":…,"axis_x":…,"axis_y":0,"axis_z":…,"max_deg":35,"turn_axis":"hinge","spin":"rudder","spin_k":35,"spin_min":-35,"spin_max":35,"spin_lag":0.3}'`
   （P 取鉸鏈在舵子作品座標裡的點；關聯原本 at 0,0,0 ⇒ at ＝ pivot ＝ P）。
5. 遊戲那側重匯之後：`__game.lostModels(0)` 不能有舵（開局就掉 ＝ stock-top 找不到船尾）；匯入檢查「轉動」那一行列出舵與舵輪。

### 9.9 裝飾（模型 meta `deco=1`；TASK-0682）

Tim 2026-10-17：「裝飾可以額外標meta 之後遊戲會有性能選項隱藏裝飾」「裝飾移除是在船隻載入時就不載入裝飾」「可以隱藏的裝飾都不算重量(遊戲機制)」。

- **標在哪**：外部模型的 meta 加 `deco=1`（`work sub=model … --arg 'meta={"deco":1}'`）。⛔ 只有外部模型能隱藏 —— 關聯標了 deco 遊戲不拿（格子是船的一部分：重量、命中照算），匯入檢查報 ⚠。
- **遊戲怎麼用**：畫質設定「裝飾」（低 ⇒ 關、中／高 ⇒ 開）。關著 ⇒ 載入船時就不載入（只給裝飾用的網格不建、不上 GPU）；開著 ⇒ 只畫。**兩種都不算重量、不被打、不掉下來**（腳下那一格甲板被打掉 ⇒ 不畫）⇒ 開或關，同一個種子戰局逐字相同。換了設定 ⇒ 下一次載入船才生效（回主選單會重載）。
- **什麼能標**：純看的東西 —— 沒當廚房的爐灶（當廚房 ⇒ `kind=galley`，§9.13）、繫纜柱、繫索栓圍欄、砲彈架、吊床網、家具這一類。
  ⛔ **不能標**：有功能 `kind` 的（砲、火藥桶、舵、門、抽水機、廚房 kind=galley、燈 kind=light …：載入時整個拿掉 ⇒ 那個功能就沒了；匯入檢查報 ⚠）；別的部件掛在它上面的（繩的端點、帆角、別的模型的固定點）—— 它不在了，掛在上面的就浮空。
  `kind=portlid`（砲門蓋板，§9.12）例外：它本身就是裝飾 kind（載入時一律拿掉），不用另標 `deco=1`。
- 裝飾不擋人也不擋砲彈，所以別把它擺在船員一定要走的路上當牆用；梯子端點、艙口照舊要留空（擺放照 §2.1 的取樣法：格心＋八角不落在現況與保留區、腳下要有甲板）。
- 匯入檢查：「裝飾」那一行列出幾個模型、這次畫幾個。
- 實例：拿破崙號 階段十五（2026-10-17）：爐灶、錨鏈繫纜柱、繫索栓圍欄 ×2、砲彈架 ×4，0.05 m 子作品、scale 0.5（`design/draft_furnish.py`、`tools/apply_furnish.py`）；遊戲讀數：開 ⇒ 畫 8 個、模型網格 70 份；關 ⇒ 0 個、65 份，三角形少 3,524；同種子 90 秒對戰 dump 開／關逐字相同。

### 9.10 槳（模型 meta `kind=oar`；槳帆船；TASK-0691）

Tim 2026-10-18：「動力跟鍋爐類似 不過只需要獎跟船員 然後獎需要有合適的動畫(非單純旋轉)」「動力件本身可以是輸出件(槳)」—— 槳 ＝ 自己出力（槳手）也自己輸出，不接主機、不接軸。

- **一支槳一個外部模型**（同螺旋槳、舵的做法：子作品用整船的框、模型 `at ＝ pivot ＝` 槳座、scale 1；一舷做好、另一舷照 `mirror=y` 擺）。槳伸在舷外 ⇒ 遊戲把它**掛在槳座 `pivot` 旁 8 格內的舷緣**上（舷緣被打掉 ⇒ 那支槳掉；⛔ 沒有 pivot ⇒ 往正下方找、找到海 ⇒ 開局就掉，匯入檢查 ✗）。
- **固定點**（子作品裡登記）：
  - **`pivot`**：槳靠在舷緣（槳架、槳孔）的那一點 —— 划槳時繞它轉、推力的作用點。⛔ 一定要有。
  - `blade`：槳葉末端。遊戲照「pivot ⇒ blade」的反方向排槳手（沒有 ⇒ 往中線排、匯入檢查 ⚠）。
  - 可選 `seat`：第一個槳手坐的那一格（腳底那一格的上一格）；沒有 ⇒ 從 pivot 往船裡 1 m。多個槳手沿槳柄每 0.6 m 一個（長槳好幾個人划一支）。
- **meta**：`kind=oar`、`rowers`（幾個槳手，預設 1）；可選 `side`（`P`／`S`）、`stroke_deg`（前後掃幾度，預設 30）、`dip_deg`（回槳時把槳葉抬出水幾度，預設 12）。
- **血量**：整支一塊（被打到扣血、歸零就斷），＝ 細節設定「砲的血量」× 道具設定頁「槳（動力件）」的倍率（遊戲 `config drvparts.oar.hpK`，預設 0.9；Tim 2026-10-18「槳太脆弱了 …三倍血量」0.3 → 0.9）。作品這邊不用標。
  `work sub=model --arg name=oar-S1 --arg source_work=<槳子作品> --arg pivot=<槳座> --arg at=<槳座> --arg scale=1 --arg 'meta={"kind":"oar","rowers":2,"side":"S"}'`
  ⚠ 模型名字不能有 `/`（`/` 留給巢狀路徑 ⇒ `name=槳/oar-S1` 被擋：「模型名字不可含 `:` `,` `|` `/` `\`」）；要分組就掛在不同的子作品裡（皇家號：舷外槳架）。
- **槳手要站得下**：槳座往船裡那一側要有甲板（或划手座）、頭上 1.4 m 空。站不下的那幾個 ⇒ 那支槳的到崗比例少幾成（開戰時廣播、匯入檢查「站不下：槳手」）。
- **遊戲怎麼用**（31_drive.js 檔頭「傳輸鏈」）：有槳的船、設定檔 `ships[].cfg.base`（划槳全速，節）> 0 ⇒ 額外動力 ＝ 槳：每支一份（份量 ＝ 槳手數 ÷ 全船槳手數）；出力 ＝ 槳還在 × 槳手到崗比例。俥鐘照用（停俥 ＝ 停槳、後退 ＝ 倒划）。
  一舷的槳被打掉、槳手倒光 ⇒ 船往那一舷偏；打舵時內側那一舷自動減槳、打滿倒划（差動轉向；畫面上內側的槳跟著停、倒著划）。倒下的槳手由預備水手補（照那支槳的位子）。
- **動畫**（只是畫面）：繞 pivot 的直立軸前後掃（出力那半拍槳葉在水裡往船尾）＋回槳時繞沿船身的軸把槳葉抬出水；同一艘同一個節奏、槳頻跟俥鐘。⇒ **槳的模型要畫在「掃到一半」的姿勢**（槳垂直於船身、槳葉剛好在水面）。
- 匯入檢查：「額外動力」那一行列出槳數（左／右舷）、槳手（站得到／要的）；沒有 pivot ✗、沒有 blade ⚠、左右舷槳數不一樣 ⚠、有槳又有螺旋槳 ⚠（只算槳）。
- 測試：夜隼號加兩舷各 4 支槳（每支 2 人）、`cfg.base` 7 ⇒ 沒風時全速 7.00 節、0→90% 11 秒（75 噸）；打掉左舷 ⇒ 每秒 +3.2°、打掉右舷 ⇒ −3.3°；左滿舵轉 180°：差動開 23 秒（直徑 39 m）、關 29 秒（63 m）。

#### 9.10.1 實際怎麼加槳（皇家號的做法；Tim 2026-10-18「把如何加槳加入造船相關文件」）

上面是「標什麼」，這一段是「照什麼順序做、量什麼」。範例：皇家號 La Réale（`apex-one-reale-01m`，2026-10-18）—— 兩舷各 32 支、每支 7 人、`cfg.base` 6；產生程式 `design/draft_oars.py`、`tools/build_oars.py`。

1. **先有划槳的地方**（槳不是單獨的東西）：每張划手座的位置與間距（史料：1.252 m，人的尺寸、不放大）、槳架或舷緣上的**槳座**（tolet，每支槳一根，立在縱樑上）、划手座的高度（槳手坐的地方要站得住：腳下實心、頭上 1.4 m 空 —— 槳的模型從他頭上過不算擋）。這些是格子（甲板、槳架子作品），槳是模型。
2. **槳做成一件通用部件**（§2.2）：一件子作品（0.05 m、模型 scale 0.5），沿 +y（y 0 ＝ 槳柄端、往 +y ＝ 槳葉），畫在「掃到一半」的姿勢：垂直於船身、往外往下一個角度（槳座高度 ÷ 往外的長度 ⇒ 槳葉中心落在水線，皇家號 11°）。
   - 尺寸照史料（皇家號：往裡 4.4 m、往外 8.6 m、槳葉 1.6 × 0.18 m、槳柄徑 0.153 → 0.09 m）；槳柄裡多少照**槳手數 × 0.6 m**（遊戲沿槳柄每 0.6 m 排一個人）—— 要剛好從槳座排到中央走道邊。
   - 固定點：`pivot`（槳柄靠在槳座的那一格）、`blade`（槳葉末端）、`seat`（第一個槳手坐的那一格 ＝ 划手座頂上一格；元件裡的座標照右舷那一支換算回來）。
   - 一支網格兩份（右舷原樣、左舷 `mirror=y`），64 支都共用 ⇒ 成品只多兩份網格（§9.4）。
3. **每張划手座擺一支**（外部模型，掛在槳座所在的子作品裡 —— 皇家號是舷外槳架 `舷外槳架/oar-S01…`）：`at ＝ pivot ＝` 槳座旁、縱樑頂上一點（槳柄的半徑）；右舷 rotate 0、左舷 `mirror=y`；meta `kind=oar、rowers、side`（`stroke_deg`／`dip_deg` 照預設就寫出來）。
   - 🩸 槳要靠在槳座**旁邊**、不是穿過它：皇家號 v1 把槳放在槳座的船尾那一格（x −1），槳柄半徑 0.75 格 ⇒ 每支跟槳座重疊 3–6 格（64 支 378 格）⇒ 挪到 x −2；槳手的 `seat` 照樣落在座上（x −1）。
   - 🩸 座的高度照**那張座的中心**量（座是一整塊、跟著舷弧走）；用槳的 x 去量 ⇒ 舷弧轉折那幾張差一格，`seat` 落在座外。
4. **量**（每一支都要）：模型格心＋八角不落在船的實心（draft_guns 的 collide；船殼、甲板、槳架、桅、舵…全算）；槳葉中心離水線（皇家號 −0.2～+1.8 格，兩頭舷弧高的那幾支比較高）；`seat` 那一格空、腳下是划手座；槳座旁 8 格內有縱樑（遊戲的掛點）；左右舷支數一樣。
   **反向對照**：少擺一支 ⇒ 那一舷少一支；一支往下沉 3 格 ⇒ 只有它報碰撞（皇家號 42 格）。
5. **遊戲那側**：`ships[].cfg.base` ＝ 划槳全速（節；皇家號 6 —— 巡航 4–5、衝刺 6–7，Musée）。有槳又有 `cfg.base` ⇒ 額外動力自動是槳，不用寫 `drive`。匯入檢查「額外動力」那一行要看到「槳 N 支（左／右）、槳手 站得到／要的」（皇家號 64 支、448／448）；沒填 `cfg.base` ⇒ 每支槳報一條 ⚠「槳不划」。
   ⚠ 槳手也是船員：皇家號開戰 542 人裡 448 個是槳手 —— 送藥手、砲班、陸戰隊的站位照樣要量（§9.3 走路格：甲板上排滿划手座時，走路格會被座切成好幾塊）。

#### 9.10.2 從船殼伸出去的槳：雙層槳帆船（持火號的做法；Tim 2026-10-18「可以加槳了 參考皇家號的配置」）

皇家號的槳靠在舷外槳架上、槳手坐在甲板上的划手座；**槳從船殼裡伸出去**的船（古代雙層／三層槳船、拜占庭 dromon、下層在甲板下划的船）另外要做下面這幾件。範例：持火號（`erina-dromon-01m`，拜占庭 dromon，2026-10-18）—— 下層每舷 25 支從外板的槳口伸出去、上層每舷 24 支從舷牆的槳口伸出去、每支 1 人、`cfg.base` 7；產生程式 `design/draft_hull.py`（開槳口）、`design/draft_oars.py`（槳元件、擺法、讀數）、`design/apply_oars.py`（落地）。

1. **槳口要真的開洞**（記號不算）：槳柄斜著穿過殼 ⇒ 洞要比槳柄**高一格**（持火號：槳柄 0.15 m、洞 0.2 × 0.3 m）；殼外張的那一段兩層殼斜著疊，打穿要多吃一格（照「外面 4 格內」挖）。洞的一圈最外那層塗深色（皮套 askoma 的樣子）。
   - `pivot` 放在**洞底往上一格**（槳柄靠在槳口下緣的槳栓上），不是洞的正中間 —— 槳柄往裡往上翹，洞的上半是讓它穿過去的。
   - 🩸 洞只有 2 格高 ⇒ 下層 4 支、上層 48 支每支在洞頂裡面那一格擦到 1–4 格（槳柄往裡翹出洞外）⇒ 改 3 格高、pivot 洞底＋1 ⇒ 0。
   - 開了洞的船殼重新落格時照差分（刻掉的、補上的分開，讀回缺 0／多 0／色差 0）；槳口開在水線上（持火號下層槳口下緣離水 0.4 m，Pryor 0.36 m）—— ⚠ 船傾到槳口泡水會不會從那裡進水沒量過。
2. **甲板下的槳手**：遊戲照站的人量（40_crew.js `standZ`：站的那一格往上 14 格要空，⛔ 不是坐姿）⇒ 甲板下淨高不到 1.4 m ＋ 座高就**不放划手座**，讓槳手站在艙底走道上（持火號：走道面 z 5、甲板橫樑底 z 18 ⇒ 剛好 14 格；史料的 0.4 m 划手座一放就頂到橫樑、14 格不夠 ⇒ 整排站不下）。艙底的關聯照 §9.3 標 `kind=deck`（持火號 `甲板-hold`「艙底（下層槳手）」）。
   - 船的兩頭艙底變窄：`seat` 那一格可能落在船殼裡 —— 遊戲會在 `seat` 旁 6 格內、照 seat 與 pivot 的高度往下找第一個站得住的格（持火號下層第 25 位站到 z 6 的殼上），**照遊戲的找法模擬一次**才算數（`draft_oars.py` 的 `rowers_game`）。
   - 艙底的隔艙壁（藥庫、艙房）讓開槳口與槳手站的那一格（持火號：藥庫隔艙壁 x 128／146 ⇒ 130／147，火藥桶跟著挪一格；第 7 位的槳手站在藥庫裡）。
3. **上層照舷弧補傾角**：下層的槳口高度一樣、一件元件的角度就對；上層的槳口跟著甲板（舷弧）走 ⇒ 船尾高的那幾支槳葉會高出水面。每支用模型 **`rotate` 的 x 角**補（右舷 −δ、左舷 `mirror=y` 時 ＋δ，δ ＝ 讓槳葉中心落在水面的角度 − 元件裡 pivot→槳葉中心的實際角度）⇒ 持火號上層 −2.8°～＋9.0°、槳葉中心離水 −0.02～＋0.03 m（下層 0）。遊戲的划槳動畫疊在模型原本的轉動上（21_gunnery.js modelLocal0：網格已照擺法轉好、swM 繞 pivot 再轉），照樣掃。
   - ⚠ 元件角度用「pivot 到槳葉中心那兩格的實際角度」算，不是設計的 angle_deg：格子取整過，差半度 ⇒ 槳葉高 0.3 m（持火號第一版上層全部 +0.33 m）。
4. **兩層兩件元件**（§2.2 通用部件）：上下層長度、入水角都不一樣（Pryor：下層 3.85 m、入水約 11°；上層較長、≥ 28°）⇒ 各一件子作品（`…-oar-lower`／`…-oar-upper`），同一層全部共用一份網格。`seat` 在槳座下面很遠（下層 1.1 m）時，元件的框往下多留幾格（`z_pad`），固定點才落在框裡。
5. **跟其他模型也要量**：§4.2 的零碰撞只算格子 ⇒ 槳的擺法另外把投石機、弩砲、舵、錨這些模型的格算進去（持火號：上層第 18 位的槳柄內端撞進投石機的底座、槳手也站不下 ⇒ 那一位不放槳、不開洞，上層每舷 24 支）。沒有 kind 的模型遊戲也當障礙（`meta_kinds.json` 沒寫 `block` ⇒ 預設要避），槳手不會站進它外框外 1 格內。

### 9.11 撞角（關聯 meta `kind=ram`；Tim 2026-10-18「有的船可以裝備撞角 故意撞敵船」）

- **標在撞角那一件的關聯上**：`kind=ram`，建議 `material=iron`（＋ `render=smooth`）；可選 `back_m`、固定點 `tip`。⛔ 不要標在整個船殼上（遊戲照這一件找撞角尖）。
- **遊戲怎麼用**（Blockside 54_helm.js helmSteerRam）：有 `kind=ram` 的船，撞角就是主武器 ⇒ 船頭對敵、指揮官不排戰列、被壓制也不拉開（撞角打不到遠處）。
  對準敵艦、照它的航速往前估（截住它）全速衝，不讓敵艦；撞上（撞擊事件結束）或船身貼上卻太慢沒撞成 ⇒ 拉開到兩條龍骨線隔 `back_m`（有動力 ⇒ 船頭對著它倒車退出來；只有帆 ⇒ 背對它跑開），再衝下一次。砲照常開。
- **撞多狠**照撞擊物理（物理設定「碰撞傷害」）：接近速度低於「撞擊門檻」（預設 1.5 m/s）不算撞擊、只是推；破壞能量照兩邊撞點的材質分（硬的分得少）⇒ 撞角要真的伸在最前面、標成鐵。
- ⚠ 慢的撞角船追不上往前跑的船（從正後方追上去接近速度太低）—— 照實：維吉尼亞號 5.5 節，撞得到的是迎面來、交叉、停著的船。
- ⛔ 皇家號這種槳帆船的 éperon、持火號的 spur 是水線以上用來壓斷敵槳、騎上敵船的木樑，不是撞破船殼的撞角 ⇒ 不要標 `kind=ram`（標了艦長就會拿它去衝撞）。
- 測試（2026-10-18，在頁面裡臨時替維吉尼亞號的「撞角」掛 `kind=ram`）：對持火號 seed 3：18.6 秒撞上（5.4 m/s），之後倒車退開、再衝；對憲法號（風 0.3）從正後方追上、5.5 對 3–4 節，只貼著推（1 m/s），改成貼上就退開助跑。

### 9.13 廚房（模型 meta `kind=galley`；TASK-0720；Tim 2026-10-19「然後可以加入廚房 廚師(可以先做簡易功能) 水手可以到廚房吃飯獲得buff」）

- **標在哪**：爐灶那一件外部模型的 meta 標 `kind=galley`（`work sub=meta part=model work=<甲板子作品> name=<爐灶> meta={"kind":"galley","deco":null}`）。只說「這是什麼」：沒有其他鍵、沒有固定點 —— 廚師與伙夫的站位由遊戲照模型外框找（同 `wheel`／`capstan`）。
- ⛔ **不標 `deco`**：有功能 kind 的不能是裝飾（§9.9：載入時整個拿掉 ⇒ 沒有廚房，戰局還會跟著畫質設定走；匯入檢查報 ⚠）。原本標了 `deco=1` 的，meta 寫 `"deco":null` 刪掉；產生程式（`design/draft_furnish.py` 這一類）裡那一列的 meta 也一起改成 `{"kind":"galley"}` —— `apply_furnish.py` 落格時 meta 是合併，不改的話重跑會把 deco 寫回去。
- **四周要留一面站得下人**：遊戲照固定順序試外框外 2 格的四個面中點（−x 船尾面 → +x 船頭面 → −y → +y），那一點 0.6 m 內要有走路格（腳下實心、頭上 1.2 m 空、不在別的模型外框裡），而且從預備水手待命的那一層沿梯子走得到。第一個成功的面給廚師站、第二個給伙夫領飯（只有一面 ⇒ 共用）。
  爐門最好朝站得下的那一面（拿破崙號的爐門朝船尾，那一面是前艙口、沒有地板 ⇒ 廚師會站到別面）。四面都不行 ⇒ 遊戲不開這座廚房（原因照列）。
- **遊戲怎麼用**（Blockside `js/45_galley.js`、`js/39_eff.js`）：
  - 爐灶變成真的模型：血量同砲、會被打、算重量；打壞 ⇒ 現成的鍋打翻、不能再做飯。
  - 有廚房的船多一位**廚師**（船員配置 `crew.cook` 是全船上限，預設 1；每座爐灶 `galley.cooks` 位），開戰就站在爐灶旁做飯，不走動；倒下不補。
  - **伙夫領飯**（照史實：Leech 1843、Masefield 1905）：船員每 `galley.mess`（8）個人物一桌，這桌吃過 `galley.hold`（90）秒就派一個閒著的預備水手當伙夫（排在所有補位之後；補位不夠人會被叫回去），走到爐灶領一鍋 ⇒ 整桌都算吃過，砲班不離開砲位。
  - 吃過飯 ⇒ **工作效率** ×(1 ＋ `lim.galley`%，預設 10%)：裝填、裝藥包、人力抽水、治療、木匠修補、帆匠補帆、救火、火槍都快一成；`galley.fade`（150）秒線性退回 1，不會低於 1。走路、爬梯、划槳不乘。
  - 廚師倒下、爐灶被打掉 ⇒ 現成的吃完就斷炊，約 4 分鐘內全船退回 1。數值都在設定檔 `galley` 那一節（admin.py `GALLEY_NUMS` 驗）；`lim.galley` 0 ＝ 整個關掉（不生廚師，網址 `?galley=0`）。
  - 沒有 `kind=galley` 的船一位元不動（不生廚師、不派人、不抽亂數）。
- **實例**：光榮號 `甲板-spar/爐灶`（`kaguya-gloire-01m-galley`，上甲板艏樓底下 x 815；2026-10-19 從 `deco=1` 改成 `kind=galley`，`id` 照留 `model-4`）；`admin.py metasync --id gloire` 只換 meta，匯入檢查「裝飾」8 → 7、⚠ 0。
- 其他有爐灶的船這一版**照舊是裝飾**：拿破崙號 `甲板-upper/爐灶`（kotoko；爐門那一面沒地板）、潮墓號 `甲板-weather/爐灶`（Sirius；露天甲板，廚師頭上沒遮蔽會被火槍打）—— 要改成廚房先跟作者說。莫尼特號、哨兵號的「廚房爐」是艙房關聯裡的一塊格子，要先拆成子作品、掛成模型（§9.8.1 那一套）才標得了。

### 9.14 被打掉怎麼演（模型 meta `blow`；TASK-0751）

Tim 2026-10-20：「物件可以標meta設定該如何演出被打飛(預設就是目前的) 然後標記一下橫桁的演出meta」。

- **兩種**：`fly`（預設）＝ 往打的方向噴出去（5–16 m/s）、往上拋、三個軸亂翻 —— 砲、舵輪這一類「被打離砲架、整件飛出去」；`fall` ＝ 被打斷：只帶一點砲彈的推力（≤ 1.5 m/s）、照重力掉、慢慢翻（約 0.3 rad/s），中心掉過 1.5 m 之後碰到船的格 ⇒ 停在那裡、跟著船走（甲板、桅樓、船舷）；掉進海裡照舊漂、沉。
- **怎麼決定**：模型 meta `blow=fly｜fall` 先看 ⇒ 沒寫照 kind（Blockside `config/meta_kinds.json` 那一列的 `blow`）⇒ 都沒寫 ＝ `fly`。現在規格表只有 `yard`（帆桁）標 `fall` ⇒ **帆桁不用一根一根標**；某一件要跟它那一類不一樣才在模型 meta 寫（`work sub=meta part=model work=<子作品> name=<模型> meta={"blow":"fall"}`，之後 `admin.py metasync --id <船>`）。
- 只管「血量歸零被打掉」那一下；腳下甲板沒了往下掉、桅斷了帆桁跟著倒，照舊。
- **只是演出**：飛出去的那一件只給人看（落水的水花用畫面的亂數），戰局照樣抽同樣次數的亂數 ⇒ 標不標，同一個種子戰局逐字相同。

## 11. 改裝船（原船當一條關聯、只存差；TASK-0656）

Tim 2026-10-16：「可以把一艘船當成子作品概念去做改裝船(減少資料量)」「概念有點像歷史上同一艘船的改型或是同級艦但略有修改」「修改可以包含挖掉原本船體上的格子 移除原有的子模組 概念類似Unity的nested prefab」「就只要記錄diff的部分(不過匯入時就要兩個一起匯入)」。

| 步驟 | 做法 | 為什麼 |
|---|---|---|
| 1. 主作品 | 改裝船自己一件（照委託建）；**原船的組裝件整艘當一條關聯**：`name=原船`、`at=0,0,0`、`turn=0` | 原船改了（重造、修 bug），改裝船下一次匯出就跟著改；改裝船的雕刻庫只有它自己加的與覆寫 |
| 2. 拿掉 | 原船裡不要的部件：那條關聯的 `link_hide=路徑,…`（關聯或外部模型；路徑相對原船，例 `駕駛塔`、`甲板-main/艙蓋-前`） | 部件連同它的模型、固定點、meta 一起不在 ⇒ 遊戲那側不會照它排站位、找舵輪 |
| 3. 挖格子 | 開一件**跟原船一樣大**的遮罩子作品（`tags=sub`），在上面畫要挖掉的格 ⇒ `link_carve=<遮罩>` | 遮罩用原船的座標（框、甲板高度、肋位都照抄原船的產生程式）；補回來 ＝ 在遮罩上 carvevox |
| 4. 新加 | 新部件照一般的子作品做，關聯到改裝船（`at` 照原船的座標）；換色用 `recolor` | 改裝船的框可以比原船大（例：加高的桅）；原船的關聯放得進就好 |
| 5. 量 | 匯出 vxk 的關聯列「放 N、照遮罩挖掉 M」；部件外框少了拿掉的；匯入檢查 | 遊戲那側照一般的船匯入（存成差是遊戲打包的事，TASK-0657） |

- ⚠ 拿掉的部件如果被別的部件的 meta 指名（例：鍋爐 `funnel=煙囪`、彈藥庫 `hoist=梯子/turret`、裝甲 `mount=甲板-main/砲塔`）⇒ 那幾條在遊戲裡會對不上；要拿掉它就連指名它的一起拿掉或換掉。（之後改用 §12 的 id 寫法，路徑改名也不會斷。）
- ⚠ 原船裡的部件只能「拿掉／挖掉／換色」，不能搬位置、改 meta —— 要動就拿掉它、在改裝船裡放一份新的。
- 實例：哨兵號（`meadow-sentinel-01m`，2026-10-16）—— 原船莫尼特號組裝件，`link_hide=駕駛塔`、`link_carve=meadow-sentinel-01m-carve`；新加司令塔、速射砲台（見作品的 notes.md）。

### 12.1 為什麼：現在的關聯有三種寫法混著用

| 寫法 | 例 | 會壞在哪 |
|---|---|---|
| 照路徑 | 裝甲 `mount=甲板-main/砲塔`、鍋爐 `funnel=煙囪`、彈藥庫 `hoist=梯子/turret`；火藥庫找桶、砲塔巢狀、砲在哪層甲板照路徑前綴 | 改名、換資料夾就斷；改裝船拆掉被指名的部件就斷（§11） |
| 照序號 | 帆腳綁哪根帆桁（footYard）、繩綁哪個模型（遊戲 `linkRopes` 存模型序號） | 中間插一件，後面全部位移 |
| 照位置猜 | 繩端點離哪個模型外框夠近就綁哪個 | 零件一換、一搬就可能綁錯 |

另外 `mount=` 同名兩義：在砲上是砲架種類（`turret`／`pivot`），在裝甲上是「跟著哪門砲」。

### 12.2 物件 id

| 項目 | 規則 |
|---|---|
| 誰有 | 每件關聯（部件）、外部模型。一個關聯裡有好幾座的（梯子、艙房）不另外發號：`<關聯 id>#<座名>`（例 `ladders-1#turret`）。繩、帆先用名字當 id —— 名字在一艘船裡本來就唯一、又不是路徑；橫繩組展開的子繩沒有自己的紀錄，發不了號 |
| 格式 | `<類別>-<序號>`，例 `gun-7`、`oar-12`、`funnel-1`、`ladders-1`、`deck-3`。類別 ＝ meta `kind`（沒有 kind 的關聯 `part`、模型 `model`）；序號只用數字（舷、桅名這些照 meta，不進 id） |
| 寫在哪 | 那一件自己的 meta：`id=gun-7`。是**擺上船的那一次**的 id（同一件砲子作品擺 54 次 ⇒ 54 個 id），不是來源子作品的 |
| 誰發 | Blockside `python -I src/admin.py ids --id <船>`：照部件清單的順序給沒有 id 的發號，用 `sculpture op=work sub=meta` 批次寫回作品（meta 不限作者，每一筆記在那件作品的 `meta_log.jsonl`），再把 id 與指名的鍵同步進 `_cache` 那份 .vxk（⛔ 不走 metasync：別人還沒匯進來的 meta 改動不會被一起帶進來）。下一號記在 Blockside `config/game.json` 的 `ships[].idNext` ⇒ 刪掉的號不重用。新船匯入後、加了部件之後跑一次（已經有 id 的不動） |
| 範圍 | 一艘船（組裝件）裡唯一 |
| 不變 | 改名、換資料夾、挪位置、重匯都不變；複製出來的一件 ⇒ 新號（發號時撞號 ⇒ 後來的那件換新號並報出來） |
| 改裝船 | 原船整艘當一條關聯帶進來 ⇒ 原船的 id 照用；改裝船自己加的用自己的號段：`<改裝船代號>.<類別>-<序號>`（例 `sentinel.gun-1`）⇒ 原船之後加東西也不會撞；原船要先跑過 `ids` |
| 同一件子作品關聯好幾次 | 裡面那幾件是同一筆紀錄 ⇒ 只有一個 id；遊戲照最近一層關聯的 id 分開：`<關聯 id>/<內部 id>`（例：哨兵號兩個彈藥櫃裡的火藥桶） |

### 12.3 關聯的寫法

- 指整件寫 `id`，指那一件上的固定點寫 `id#固定點`（例 `gun-7#breech`、`sail-4#<角名>`）。
- 欄位一覽（舊 ⇒ 新）：

| 誰 | 舊 | 新 |
|---|---|---|
| 裝甲跟著哪門砲 | `mount=<砲的路徑>` | `mount_of=gun-7`（`mount=` 只留給砲架種類） |
| 鍋爐的煙囪 | `funnel=<路徑>` | `funnel=funnel-1` |
| 主機的螺旋槳 | `propeller=<路徑>` | `propeller=propeller-1` |
| 彈藥庫從哪座梯子吊火藥 | `hoist=<梯子路徑>` | `hoist=ladders-1#turret` |
| 帆腳綁哪根帆桁 | 照帆腳那條繩的 `ends` 找帆桁模型（本來就是照名字，查過不是序號） | 不改 |
| 繩的兩端 | 作品的 `ends` 有寫 `model:<模型>/<固定點>`，遊戲卻照外框猜綁哪個模型；模型排在母繩前面 | **匯入時**照同一套規則算好每一端綁在哪、寫進 `.vxk`（`rig.ropes[].bind`），遊戲照它綁、執行時不猜（Blockside `admin.py ropebind`，匯入／重新匯入／metasync／ids 會自己跑，報表 `reports/ropebind_<船>.md`）。順序：砲塔的殼 → 作品寫明的（`model:` 那個模型、`rope:` 只找繩、`sail:` 與固定點不猜模型）→ 帆桁 → 母繩（≤ 3 格）→ 最後才照外框猜模型（報表列出來）。雕刻端檢查：`work sub=ropecheck`（§10）。改寫成 `gun-7#breech` 留到掛點那一段（TASK-0714） |

- 規格表（Blockside `src/config/meta_kinds.json`）每一類登記 `refs`：哪些欄位是關聯、能指哪幾類。
- 匯入檢查：沒有 id ⇒ ⚠；撞號 ⇒ ✗；指到不存在的 id ⇒ ✗；類別不對 ⇒ ✗；`#` 後面那一座不存在 ⇒ ✗；繩端只靠照位置猜才綁上 ⇒ ⚠；舊寫法 ⇒ ⚠。
- 量過（2026-10-18）：作品寫明綁在模型上的繩端 3,048 個，照外框猜錯 98 個 —— 風暴角號 P1 砲的 breeching 綁到 S1 砲、潮墓號 96 條砲尾的繩綁到旁邊的導纜器。改照 `ends` 之後這兩艘的戰局跟著變（修好的）；另外 715 個繩端遊戲先綁船殼的格子（旁邊 5 格內有格），這一條沒改。
- 量過（2026-10-18，TASK-0716）：改成上面的順序之後 17 艘照外框猜的 0 端、哪裡都不靠的 0 端 —— 以前被猜到模型上的 409 端（潮墓號 384、風暴角號 20 …）其實都接在別的繩上或作品寫明了；雕刻端 `ropecheck` 也只找到炎羽號 2 端要挪（20 cm）。

### 12.4 掛點：原本雕的零件 ＝ 可換零件的位子

- 每一件可換零件同時是一個**掛點**：id 不變，只多記「現在裝的是哪一件」。換裝表 `{ "gun-7": "32c" }`。
- **沒換 ⇒ 裝的就是原本雕的那一件**（網格、固定點、meta 都照原本）⇒ 戰局跟沒有這套時逐位元相同。
- 換了 ⇒ 從零件表拿那一件的網格與固定點，照掛點的座標系擺上去；meta 換成那一件的（種類、重量、要幾個人）。站位、重量、家具擋格照新的重算；繩端寫的是 `id#固定點` ⇒ 跟著新零件同名的固定點走。
- 同一類零件要有同一組固定點名字（零件表那一件缺 ⇒ 不收進表）。

| 類 | 座標系（照原零件的固定點） | 能換成 |
|---|---|---|
| 砲 | `trunnion`＋`breech`→`muzzle` | 同一種砲架（舷側、迴旋、旋轉砲座 pivot、砲塔 turret） |
| 槳 | `pivot`＋`pivot`→`blade` | 槳 |
| 舵 | `stock-top`＋舵軸 | 舵 |
| 螺旋槳 | 軸線（實作那一段定固定點名字） | 螺旋槳、明輪 |
| 舵輪 | `hub-aft`→`hub-fore` | 舵輪 |
| 燈 | `wick` | 燈（可拆空） |
| 小艇、絞盤、格柵、羅經櫃、裝飾 | 外框底面中心＋船的方向 | 同一類（小艇、裝飾可拆空） |

- meta `fits=<類,…>` 放寬或收窄能換的；`optional=1` ＝ 可以拆空。
- 放不下（外框超過原件太多、類別不合）⇒ 不換、開戰時廣播、匯入檢查報。
- **不當掛點**：帆桁（綁著帆與繩，算帆裝）、火藥桶（火藥庫的存量，走家具那一套）、門（跟船殼開口綁死）。
- **先改成模型才當掛點**：主機、鍋爐、錨（現在烤在格子裡；照螺旋槳自己帶體素的做法）；軸與蒸汽管跟著主機、鍋爐的位置。
- **結構，不動**：船殼、甲板、桅、梯子、艙房、彈藥庫、裝甲。

### 12.5 存在哪

| 什麼 | 在哪 |
|---|---|
| id | 作品裡每一件的 meta（雕刻端） |
| 零件表 | 建置時從現有船上收（相同網格共用），跟船一起內嵌進成品 |
| 出廠換裝表 | Blockside `config/game.json` 的 `ships[].fit`（後台頁改） |
| 玩家的換裝表 | 跟船員配置、艙房同一套存檔與匯出匯入；同一型、換裝不同 ⇒ 各建一份船型 |
